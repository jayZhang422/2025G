# 2026 年电赛信号类赛题研判与当前 25G 架构改进建议

> 日期：2026-07-25  
> 工程：`25G_PL` + `25G_PS`，Zynq-7020  
> 判断原则：赛题方向以给定的五份研判材料为前提；任何涉及当前硬件接口、数据流、采样率、帧长、算法和验证状态的歧义，以当前仓库 RTL、Block Design、BSP、PS 源码、构建报告和板上日志为准。

## 一、结论先行

如果给定材料对 2026 年器件清单的解读成立，今年信号类题目最可能不是单独考“万用表”或某一种“调制器”，而是考一个共同母题：

> 对宽动态范围信号完成产生、调理、采集、识别和校准，再叠加自动量程、相敏检测、扫频测量或调制解调中的一项。

结合当前工程，我的判断是：

1. 当前工程已经具备一个较强的专用数字底座，不需要推倒重来。
2. 当前最成熟的能力是“双分量正弦/三角波识别与双 DDS 重建”，不是通用信号测量。
3. 当前最有价值的可扩展资产是 PL 单频 I/Q，相比重新增加 PL FFT，它更适合微弱信号和相敏测量。
4. 当前最严重的限制不是 FPGA 资源，而是采集模式、模拟前端、校准和系统验证。
5. 如果题目要求瞬态、连续调制波形或无缝记录，当前逐帧轮询 DMA 不满足要求。
6. 如果题目要求网络分析或阻抗测量，当前单通道 ADC 是硬门槛。
7. 如果题目要求自动量程，当前没有 PGA、衰减器控制、比较器和档位校准，数字算法本身无法补足这些缺口。
8. 如果题目偏微弱信号检测，当前 IQ 路线最接近可快速形成竞争力的方向。

因此，推荐总体策略是：

> 保留现有三条主路径，先把它们变成“帧可信、结果有单位、错误可定位”的可靠测量底座；再优先扩展自动量程或微弱信号方向。网络分析必须先解决双通道同步采样，调制解调必须先明确需要处理的调制方式。

## 二、今年可能出现的赛题方向

以下排序是备赛投入优先级，不是严格概率。

| 排名 | 候选母题 | 可能性判断 | 与当前工程的适配度 | 核心原因 |
| --- | --- | --- | --- | --- |
| 1 | 自动量程的综合信号参数测量仪 | 高 | 中 | ADC、DDS、比较器、PGA/VGA 和显示可形成完整链路；当前缺模拟量程和通用测量 |
| 2 | 微弱信号检测、相敏检波或简化锁相放大器 | 中高 | 中高 | 当前已有 ADC 域 48 位 I/Q 积分，这是最可复用的特征路径 |
| 3 | 扫频、幅频相频、阻抗或简易网络分析 | 中高 | 中低 | 已有双 DDS 和 IQ，但只有单通道 ADC，不能同步测参考与响应 |
| 4 | 调制、混频、频率搬移与参数识别 | 中 | 中低 | 当前 FFT 可搜索频率，但没有流式 I/Q 基带、CIC/FIR 和连续采集 |
| 5 | 波形发生、测量和校准一体化仪器 | 中 | 中高 | 双 DDS/DAC 和采集路径可复用，但还缺物理单位、校准和交互配置 |
| 6 | 高精度直流或低频测量 | 中低 | 低 | 当前 AD9226 为 12 位高速路径，没有精密基准、低漂移前端和多量程体系 |

### 2.1 最可能的题目包装

更可能出现的不是纯单功能题，而是以下组合之一：

- 未知输入幅度跨度较大，系统自动选档并测量频率、有效值、波形或失真；
- DDS 产生激励，系统测量被测网络的幅值或相位响应；
- 从噪声或干扰中提取已知频率的微弱信号；
- 对 AM、DSB-SC、ASK、FSK 或混频后的信号测量参数并恢复低频信息；
- 比较器给出过零或阈值事件，ADC 给出幅值，二者联合完成测量；
- 作品既要输出信号，也要对输出或被测响应进行自检和校准。

### 2.2 不建议重押的方向

- 不建议仅凭五位半万用表重押“24 位 ADC 万用表”。仪器清单更可能表示需要高精度验收和校准。
- 不建议仅凭乘法器重押传统通信题。乘法器同样适合相敏检波、功率测量、混频和幅相测量。
- 不建议赛前一次性准备完整 AM、FM、ASK、FSK、QPSK 协议栈。应先准备可复用的 I/Q、Goertzel、频偏估计和连续数据路径。

## 三、当前实际工程基线

### 3.1 已有数据路径

```text
单通道 AD9226 12 bit，约 5.12006 MSPS
 → ADC 相移时钟寄存
 → 独立时钟 FIFO
 → {ADC[11:0], 4'b0} 的 16 bit AXIS
 → 每 4096 次有效握手产生 TLAST
 → BD AXIS FIFO
 → AXI DMA Simple S2MM
 → HP0 DDR
 → PS Cache 管理
 → 4096 点 CMSIS RFFT
 → 双频候选与正弦/三角联合残差判别
```

DMA 当前是：

- Simple Mode；
- 仅 S2MM；
- 轮询完成；
- 无 DMA 中断连线；
- AXIS 侧 16 位；
- 内存侧 64 位；
- 无 DRE；
- 固定 4096 点、8192 字节一帧。

### 3.2 已有输出路径

```text
PS AXI BRAM
 → 十字控制快照
 → COMMIT_SEQ 原子提交
 → A/B 独立 32 bit DDS
 → 正弦/三角 ROM
 → 幅度缩放和 14 bit 饱和
 → AD9767 双通道输出
```

当前 DDS 路径的优点是配置原子性较好，A/B 频率、相位、幅度和波形不会在不同 DAC 时刻部分生效。这个结构应保留。

### 3.3 已有特征路径

```text
ADC 域 12 bit 样本
 → 正交 DDS sin/cos
 → I/Q 乘法
 → 48 bit 定长积分
 → 稳定快照与结果序号
 → AXI-Lite
 → PS 计算幅值和 atan2 相位
```

PL IQ 已具有单频和扫频相关寄存器基础，但当前 PS 驱动每次固定配置：

- `SCAN_STEP = 0`；
- `SCAN_COUNT = 1`；
- `WINDOW = 4096`；
- 只对锁定后的两个频点各测一次并打印。

因此当前 IQ 是“已实现的硬件基础”，还不是完整的扫频或微弱信号业务模块。

### 3.4 当前实现与资源余量

最新实现报告为 2026-07-24：

| 资源 | 使用量 | 器件总量 | 占用率 |
| --- | ---: | ---: | ---: |
| Slice LUT | 4237 | 53200 | 7.96% |
| Slice Register | 7613 | 106400 | 7.16% |
| Block RAM Tile | 23 | 140 | 16.43% |
| DSP | 4 | 220 | 1.82% |

路由后时序摘要：

- WNS：0.302 ns；
- WHS：0.036 ns；
- TNS/THS：0；
- Vivado 报告内部用户时序约束满足。

因此 PL 资源仍很充足，暂时没有必要为了节省少量资源牺牲可观测性或模块清晰度。但资源富余不等于外部 ADC/DAC 时序已经闭合。

## 四、最近板上日志说明了什么

最近一次板上运行最终正确识别出 25 kHz 三角波和 75 kHz 正弦波，并进入 `RUNNING`，说明：

- DMA、DDR 和 Cache 的正常采集路径可工作；
- 4096 点 FFT 和联合残差算法可在真实输入上锁定；
- DDS A/B 配置和原子提交正常；
- PL IQ 可以完成两个频点的结果快照；
- 新增 monitor 的寄存器访问和 64 位拼接正常。

但同一份日志也给出了必须正视的问题。

### 4.1 ARMED 等待期间持续丢样

启动 monitor 快照中：

```text
valid        = 0x02268E2B
written      = 0x000012C0
blocked_full = 0x02267B6B
status       = 0x2A
```

计数关系严格满足：

$$
0x02268E2B=0x000012C0+0x02267B6B
$$

`status=0x2A` 表示快照有效、发生过写阻塞、当前 `prog_full`。这说明 PS 等待按键时 ADC 继续采样，但 DMA 没有消费，FIFO 很快填满，之后绝大多数样本被阻塞。

这不一定是当前稳定信号识别题的功能错误，但必须明确其语义：

> 当前 ARMED 状态不是“保存了按键前的连续波形”，而是“持续采样并持续丢弃，等到按键后再从已有 FIFO 状态开始取一帧”。

### 4.2 第一帧不是完整帧

第一帧 DMA 日志报告 `BTT=0x1FE8`，即 8168 字节，而完整帧应为 8192 字节。差值对应：

$$
N_{missing}=\frac{8192-8168}{2}=12\ \text{samples}
$$

这与第一帧出现异常高码和锁定拒绝一致。后续帧恢复为 `0x2000`，当前三帧确认机制最终避开了启动脏帧，但这属于算法容错掩盖了采集边界问题，不能作为通用框架的正常设计。

### 4.3 PS 无法逐帧处理当前原始流

当前帧时间为：

$$
T_{frame}=\frac{4096}{5.12006\times10^6}\approx0.8\ \text{ms}
$$

板上日志中 PS 分析耗时约为 117 ms、342 ms、695 ms 和 706 ms。处理时间与帧时间的比值约为：

$$
\frac{T_{process}}{T_{frame}}\approx146\sim883
$$

原始 AXIS 数据率仅为：

$$
R=5.12006\times10^6\times16\approx81.92\ \text{Mbit/s}
$$

$$
R\approx10.24\ \text{MB/s}
$$

这个带宽对 HP0 DDR 并不高。真正瓶颈是：

- PS 只提交单次 DMA；
- CPU 每帧执行复杂浮点 FFT 和多次联合残差重建；
- 处理期间没有新的有效接收缓冲提交；
- 算法速度远低于 1250 帧每秒的输入帧率。

因此即使马上改成双缓冲，PS 也不可能逐帧完成当前联合分析。必须先定义数据丢弃策略、结果刷新率和 PL/PS 算法分工。

## 五、当前框架做得好的部分

### 5.1 PS/PL 分工基本合理

- ADC 接口、CDC、固定节拍 DDS 和 I/Q 积分放在 PL；
- FFT、候选解释、状态机、开方和反三角计算放在 PS；
- 没有为了“使用 FPGA”而把所有浮点业务硬件化。

### 5.2 专用识别算法具有真实竞争力

当前算法不仅找两个最大频谱峰，还实现了：

- ADC 去直流；
- Hann 窗；
- 4096 点 RFFT；
- 三点谱峰插值；
- 5 kHz 栅格吸附；
- 正弦/三角四种组合枚举；
- 三角波奇次谐波建模；
- 双分量联合时域残差；
- 三帧一致后锁定；
- 五组合成输入启动自测。

这套算法应作为“专用识别模式”保留，而不是为了通用化直接删除。

### 5.3 DDS 原子提交设计值得保留

影子寄存器和 `COMMIT_SEQ` 使 A/B 配置一次生效。它非常适合后续扩展扫频、校准和自动测试，不应轻易重写。

### 5.4 monitor 已形成基本故障定位能力

现在已经能区分：

- ADC 有效样本是否持续到达；
- 原生 FIFO 实际写入多少；
- 因 `prog_full/full` 阻塞多少；
- 因 reset busy 阻塞多少；
- AXIS 成功握手多少 beat；
- 发送了多少个 `TLAST`；
- AXIS stall 持续多久。

这比增加更多 DSP IP 更重要，因为后续每个 DMA 或处理改动都有客观计数依据。

### 5.5 PL 资源足以支持有选择的扩展

当前 LUT、寄存器和 DSP 占用均较低，可以增加小型统计模块、比较器计数、触发、采集控制和少量滤波。真正需要控制的是验证复杂度，而不是资源占用。

## 六、当前不足和问题

## 6.1 P0：必须先解决的问题

### 6.1.1 第一次正式采集缺少明确帧对齐

当前 DMA 只在启动失败、状态错误或超时时执行丢弃帧重对齐；正常上电后第一次采集不会先对齐。最近日志已经证明第一帧可能提前遇到 `TLAST`。

最小修正思路：

1. KEY1 被接受后，正式分析前执行一次丢弃到下一 `TLAST`；
2. 或增加 PL 采集使能/软 flush，使 H_top 帧计数器、AXIS FIFO 和必要的 ADC FIFO 读侧在同一恢复流程中重新建立边界；
3. 记录正式采集前后的 monitor 计数器差值；
4. 若一帧期间出现新的 blocked、reset busy 或帧计数异常，拒绝该帧。

第一阶段优先采用 PS 丢弃帧，因为改动最小；如果板测发现 DMA reset 后流仍不能稳定重建，再增加 PL 级 flush。

### 6.1.2 必须明确“间歇测量”还是“连续采集”

当前框架适合稳定周期信号的间歇测量，不适合：

- 瞬态捕获；
- 调制波形连续解调；
- 触发前后记录；
- 无缝数据保存；
- 每帧都必须处理的快速变化信号。

应先定义模式：

| 模式 | 当前是否支持 | 推荐实现 |
| --- | --- | --- |
| 稳态快照测量 | 基本支持 | 启动对齐后保留 Simple DMA 轮询 |
| 连续采集、只处理最新帧 | 不支持 | DMA 中断 + ping-pong，CPU 明确丢弃旧帧 |
| 连续保存原始波形 | 不支持 | SG/cyclic DMA 或较大环形缓冲 |
| 高速输入、低速结果 | 部分支持 | PL IQ、统计、抽取，仅向 PS 输出特征 |
| 触发前后波形 | 不支持 | PL 环形 RAM + 触发控制 + DMA 搬运 |

对于当前 CPU 性能，最现实的通用模式是“DMA 连续收，CPU 只处理最新完整帧”，或“PL 先提取特征，PS 低速解释”。

### 6.1.3 DMA 帧只有裸样本，没有逐帧元数据

当前每帧只有 4096 个 16 位样本，没有：

- 魔数和格式版本；
- 帧序号；
- 采样率编号；
- 增益/量程编号；
- 触发时间戳；
- 该帧对应的 overflow、blocked 或 reset 状态。

monitor 解决了累计状态不可见的问题，但 monitor 快照与 DMA 某一帧并不是天然原子绑定。第一阶段不建议直接把帧头插入样本流，因为这会改变 DMA 长度和 FFT 输入格式。更小的做法是由 PS 在采集前后各取一次 monitor 快照，形成帧外描述符并判定计数增量。只有连续记录或多通道格式确有需要时，再设计 AXIS `TUSER` 或独立 descriptor 流。

### 6.1.4 当前算法过度绑定旧题型

以下参数均为编译期固定值：

- 4096 点；
- 5.12006 MHz；
- 20–100 kHz 搜索带；
- 5 kHz 频率栅格；
- 只允许两个分量；
- 波形类型只有正弦和三角；
- 最小分量间隔 2.5 kHz；
- 三角波建模到 15 次谐波；
- 连续三帧确认；
- 18 秒锁定超时。

这不是当前专用任务中的错误，但如果继续把它作为唯一业务模式，就会直接限制正式赛题适配。建议保留现有算法，并增加独立的“通用测量模式”，不要把旧算法强行改造成万能算法。

此外，当前 `dds_control_from_component()` 始终使用统一满幅码，输出相位主要来自预设 A/B 相位和 B 通道 180°补偿，而不是复现识别结果中的实际输入幅值和绝对相位。这符合当前“识别后产生指定输出”的逻辑，但不等于通用波形重建或校准信号源。

### 6.1.5 没有经过校准的物理量

当前输出主要是：

- ADC 码值范围；
- 算法内部基波幅值；
- 未归一化的 IQ 幅值；
- 未扣除系统延迟的相位；
- DDS 幅度码。

它们不能直接解释为 V、Vrms、dBV、dBm 或被测网络绝对相位。

最小 ADC 模型应为：

$$
V_{in}=K_{ADC}(f,g)(Code-Code_0(g))
$$

其中 `g` 是量程/增益档位。IQ 相位至少需要补偿固定时延：

$$
\varphi_{cal}(f)=\operatorname{wrap}\left(\varphi_{raw}(f)-\varphi_0-2\pi f\tau\right)
$$

DDS 实际频率应由量化后的相位步进反算：

$$
f_{DDS,real}=\frac{FCW}{2^{32}}f_{DDS,clk}
$$

当前固定的 B 通道 180°补偿只是一个已知硬件 workaround，不等于完整幅相校准。

### 6.1.6 ADC 板级输入时序没有闭合

最新 Vivado 报告虽然 WNS 为正，但 XDC 没有针对 `i_ad_data[11:0]` 的 `set_input_delay -min/-max`。方法学报告还存在：

- `TIMING-4` Critical Warning：主时钟重复/无效定义；
- `TIMING-27` Critical Warning：层级引脚上的无效主时钟；
- `TIMING-9`：未知 CDC 逻辑；
- `TIMING-10`：同步器缺少属性；
- `TIMING-18`：29 个端口缺少输入或输出延时；
- 大量旧 ILA、SmartConnect 和内部层级约束找不到对象的 Critical Warning。

因此“内部时序满足”不能等价为“AD9226 采样窗口已经证明”。必须根据 AD9226 数据手册、PCB 偏差和相移采样关系补齐板级时序模型，并清理失效约束。

### 6.1.7 文档和版本标识已经落后于源码

当前文档仍有以下不一致：

- `25G_PS/.ai/PLagriculture.md` 仍称 FIFO overflow 没有 PS 可见状态，但 monitor 已经存在；
- 根目录当前架构文档没有记录新 monitor、DMA 专用 section 和超时重对齐；
- `PLagriculture.md` 仍使用 `2023H` 标题和旧自动化路径；
- PS 构建标签仍为 `FREERTOS_IQ_DMAFFT_20260723`，不能反映 7 月 25 日的 DMA/monitor 修改。

赛场上 bitstream、XSA、BSP 和 ELF 版本不匹配会产生非常难查的错误。应增加统一硬件构建 ID，并让 PS 启动时打印和检查。

## 6.2 P1：形成通用测量能力

### 6.2.1 增加通用基础测量

建议在 PS 增加独立模块，不改变现有专用分类器：

- DC 均值；
- 总 RMS；
- 去 DC 的交流 RMS；
- 最大值、最小值、峰峰值；
- 饱和点数和过载状态；
- 任意频率的 FFT 峰值，不强制吸附 5 kHz；
- 可选 Hann 窗增益修正；
- 单边谱、dBV、THD 的基础版本。

基础公式为：

$$
x_{DC}=\frac{1}{N}\sum_{n=0}^{N-1}x[n]
$$

$$
x_{RMS,AC}=\sqrt{\frac{1}{N}\sum_{n=0}^{N-1}(x[n]-x_{DC})^2}
$$

$$
x_{PP}=\max(x[n])-\min(x[n])
$$

通用测量和专用识别应作为两个业务入口共享同一采集服务。

### 6.2.2 增加最小串口命令行

当前固定日志对带回实验室调试足够，但比赛时改变参数仍需重新编译。建议至少支持：

```text
status
capture
dump 64
measure
dds A/B freq amp phase wave
iq freq window repeat
cal show/zero/gain/phase
counters snapshot/clear
reset dma
selftest
```

第一版可以阻塞执行，不需要复杂 shell 或 UI。

### 6.2.3 建立黄金模型和回归数据

当前五组合成自测只验证专用算法。还需要离线生成：

- 任意非 5 kHz 栅格正弦；
- 带 DC 和噪声的信号；
- 幅度接近满量程和小信号；
- AM、FSK 或扫频数据；
- 缺样、重复样本、短帧和错帧；
- 已知 RC/RLC 幅相数据。

黄金结果至少包括频率、RMS、峰峰值、FFT、I/Q、相位和允许误差。

### 6.2.4 建立板级长期测试

monitor 已经使长测具备可操作性。每次测试应记录：

- 总 ADC valid；
- FIFO write；
- blocked full/reset；
- AXIS beat 和 frame；
- DMA 成功、超时、重对齐次数；
- 每帧处理耗时；
- ADC 饱和点数；
- 频率、幅值、相位误差；
- 软件和硬件版本；
- 10 分钟、1 小时和数小时结果。

## 七、当前完全缺少、且取决于赛题方向的硬件

这些不是现有代码小修能够解决的内容。

### 7.1 自动量程方向

当前顶层只有单路 AD9226 数据、双 DAC、按键和 Zynq 固定接口，没有：

- 输入保护；
- 可切换衰减器；
- PGA/VGA 控制；
- 抗混叠滤波档位；
- 快速过载比较器；
- 每档零点/增益校准。

自动量程状态机应包含：

```text
粗测 → 选档 → 等待模拟建立 → 丢弃过渡帧 → 精测
  ↑                                      │
  └──────────── 滞回升/降档 ─────────────┘
```

阈值应满足：

$$
A_{up}<A_{down}<A_{FS}
$$

大信号立即降增益，小信号连续多次满足才升增益。切档后的数据不能直接参与测量。

### 7.2 网络分析和阻抗方向

真正的传递函数需要同时测量参考和响应：

$$
H(f)=\frac{Y(f)}{X(f)}
$$

当前只有一个 AD9226 通道，双通道 DAC 输出不能代替双通道 ADC 输入。因此当前最多能做经基准标定的顺序幅频测量，不能等价为真正双通道网络分析仪。

若主攻该方向，必须增加：

- 双通道同步 ADC 或可靠同时采样前端；
- 参考/响应通道统一时钟和触发；
- 两路增益差与固定时延校准；
- PS 复数比值、相位展开和夹具去嵌入；
- 最好让 DDS/DAC 与 ADC 共用参考时钟。

当前 DAC 时钟来自 PS FCLK 派生的 125 MHz，而 ADC 采样时钟来自外部 50 MHz 经 PLL 派生。两者不是当前工程中明确证明的同源相干时钟。做绝对相位或长积分回环前必须处理频差和相位漂移。

### 7.3 微弱信号方向

这是当前最容易扩展的特色方向。建议优先增加：

- PS 可配置 IQ 窗长、重复次数和频点列表；
- 使用 `RESULT_PINC` 对应的真实参考频率；
- 多次 I/Q 的均值、方差和置信度；
- 背景测量与复数背景扣除；
- 可变积分时间与结果刷新率选择；
- ADC/IQ 饱和检查；
- 低噪声模拟前端和可控增益；
- 常用频点幅相校准。

积分时间与等效噪声带宽近似满足：

$$
B_{eq}\propto\frac{1}{T_{int}}
$$

无需优先加入 PL CORDIC。IQ 结果更新率很低，幅值开方和相位计算放在 PS 更容易校准。

### 7.4 调制解调方向

当前双 DDS/DAC 只能生成两路连续正弦或三角波，并通过低速 BRAM 快照更新参数。它不具备：

- 连续 I/Q 基带样本流；
- 脉冲成形；
- 符号时钟；
- 流式 AM/FM 调制；
- 数字下变频后的连续 I/Q 输出；
- CIC/FIR 抽取；
- 持续调制波形 DMA。

因此不能把“双通道 DDS”直接称为“IQ 调制器”。若主攻调制解调，应先选定一到两种调制方式，再增加最小数据通路。例如：

- ASK/FSK：比较器或双 Goertzel；
- AM/DSB-SC：包络与单频同步检波；
- FM：复基带相位差分；
- 通用低中频接收：NCO、复乘、CIC/FIR、抽取和低速 I/Q DMA。

### 7.5 高精度直流/低频方向

当前 12 位 AD9226 快速采集路径不适合直接追求五位半直流精度。若题目偏该方向，建议新增并行的低速精密测量模块，而不是破坏现有高速路径：

- 18～24 位 Σ-Δ ADC；
- 精密参考和低漂移前端；
- 输入保护与多量程电阻网络；
- 50 Hz/60 Hz 抑制；
- 零点、增益、温漂和重复性记录。

理论量化位数不是系统有效位数。有效位数仍应由实测 SINAD 估算：

$$
ENOB=\frac{SINAD-1.76}{6.02}
$$

## 八、推荐的最小目标架构

不建议重写当前工程。推荐在现有结构上增加四个边界清楚的小层次：

```text
模拟前端
  输入保护 / 衰减 / PGA / 抗混叠 / 比较器
         │
         ▼
现有 PL 采集主干
  AD9226 → ADC FIFO → AXIS → DMA
              ├→ FIFO/AXIS monitor
              ├→ IQ 特征路径
              └→ 可选帧统计/触发
         │
         ▼
PS 采集服务
  启动帧对齐 → DMA所有权 → 帧质量判定 → 快照/连续模式
         │
         ├→ 通用测量：DC/RMS/Vpp/FFT/IQ
         ├→ 现有专用模式：双分量正弦/三角识别
         ├→ 方向模块：自动量程/扫频/微弱信号/解调
         └→ 校准、CLI、日志与错误恢复
         │
         ▼
现有双 DDS/DAC 原子输出
```

建议将工作模式明确为：

```text
BOOT → SELF_TEST → IDLE → ALIGN → ACQUIRE → VALIDATE → PROCESS
                    ↑                              │          │
                    └──────── ERROR_RECOVERY ←─────┘          │
                    └──────────────── DISPLAY/OUTPUT ←────────┘
```

当前 `ARMED → LOCKING → RUNNING` 状态机可以作为专用模式内部状态机保留。

## 九、分阶段改进顺序

## 9.1 第一阶段：先把当前采集定义清楚

目标：不增加新题型能力，只解决首帧和帧质量。

1. KEY1 后正式分析前执行一次启动重对齐；
2. 每次采集保存 monitor 前后快照；
3. 增加帧质量判定，拒绝短帧、blocked 增长和 reset busy 帧；
4. 增加 DMA 成功、失败、超时和重对齐次数；
5. 更新软硬件构建 ID 和架构文档。

完成标准：

- 第一帧稳定为 8192 字节；
- 第一帧不再出现旧缓冲尾部；
- 人为等待、暂停 DMA 和复位后，计数关系可以解释；
- 软件明确打印当前是快照模式还是连续模式。

## 9.2 第二阶段：形成通用测量最小闭环

目标：不依赖 PGA 和双 ADC，也能成为基本测量仪。

1. 增加 DC、AC RMS、总 RMS、Vpp 和饱和；
2. 增加不吸附 5 kHz 栅格的通用频率测量；
3. 建立 ADC 码值到电压的零点/增益校准；
4. 建立 DDS 常用频点幅度校准；
5. 建立 IQ 常用频点幅相修正；
6. 增加最小串口命令行；
7. 建立 Python/MATLAB 黄金数据。

完成标准：

- 串口输出明确使用 V、Vrms、Hz 和 degree；
- 同一输入重复测量有误差统计；
- 任意非 5 kHz 栅格正弦可正确测频；
- 校准前后误差表可以证明改善。

## 9.3 第三阶段：按母题选择模拟和数字扩展

推荐只选一个主方向和一个备用方向：

### 主方向建议 A：自动量程综合测量

- 增加保护、衰减、PGA 和比较器；
- 实现切档滞回、建立等待和过渡帧丢弃；
- 每档独立校准；
- 增加比较器多周期测频和快速过载。

### 主方向建议 B：微弱信号/相敏检测

- 完善现有 IQ 驱动和统计；
- 增加低噪声模拟增益；
- 做背景扣除和积分时间切换；
- 完成 DDS/ADC 时钟相干性处理与幅相校准。

### 只有明确选网络分析时

- 增加同步双 ADC；
- 再做扫频、复数比值、相位展开和夹具校准。

### 只有明确选调制解调时

- 明确调制类型；
- 再做连续 DMA、数字下变频、抽取和相应判决算法。

## 9.4 第四阶段：连续采集按需求升级

升级顺序建议：

1. 保持 Simple DMA，先做启动对齐和快照测量；
2. 若需要更高刷新率，连接 DMA 中断并做 ping-pong；
3. 明确缓冲区 `FREE`、`DMA_OWNED`、`CPU_READY`、`CPU_PROCESSING` 状态；
4. CPU 跟不上时只处理最新完整帧，不覆盖正在处理的缓冲；
5. 只有题目要求连续记录或触发前后波形时再做 SG/cyclic DMA。

不要把“改成 SG”当作性能问题的唯一答案。当前联合算法慢数百倍，必须同时降低处理率、优化算法或把低速特征放到 PL。

## 十、当前不建议做的事情

1. 不要优先加入 PL FFT。当前 PS FFT足以服务快照搜索，先完成校准和数据可信度。
2. 不要为了资源利用率低就塞入大量 DSP IP。资源不是当前主要矛盾。
3. 不要先做复杂 SG DMA。当前 CPU 处理速度决定了即使 DMA 连续，算法仍无法逐帧运行。
4. 不要把双 DAC 误认为双 ADC，也不要据此宣称能完成双通道网络分析。
5. 不要把 IQ 原始幅值直接标成电压，也不要把未校准相位直接当成被测网络相位。
6. 不要大规模重构现有 FreeRTOS 和专用状态机。先把历史 `.txt` 主流程恢复为普通 `.c/.h` 即可。
7. 不要用锁定算法成功来替代 DMA 连续性验证。稳定周期信号可以容忍大量丢帧，调制和瞬态不能。
8. 不要在没有双通道和同源时钟之前投入复杂相位展开 UI。
9. 不要在板级输入时序未闭合时继续提高 ADC 采样率。

## 十一、建议建立的验收表

| 类别 | 最低验收项目 |
| --- | --- |
| 采集 | 首帧长度、连续帧长度、DMA 错误、blocked、frame/beat 计数关系 |
| 性能 | 采集时间、处理时间、最大结果刷新率、CPU 占用 |
| ADC | 零点、噪声、Vpp、RMS、饱和、频率响应、输入时序 |
| DDS/DAC | 实际频率、幅度平坦度、偏置、A/B 差异、杂散 |
| IQ | 幅值比例、相位偏置、时延斜率、积分时间、底噪 |
| 校准 | 版本、日期、CRC、校准前后误差、失效处理 |
| 稳定性 | 10 分钟、1 小时、数小时，软件复位和 DMA 恢复 |
| 版本 | bitstream、XSA、BSP、ELF 和构建 ID 一致性 |

每项都应给出数值和允许误差，而不是只写“通过”。

## 十二、最终评价

当前 25G 工程不是一套差的架构，反而已经具备三个难得的基础：

- 可工作的 ADC、FIFO、AXIS、DMA 和 PS FFT 主路径；
- 原子控制的双 DDS/DAC 输出；
- 已进入 bitstream 的 ADC 域 I/Q 特征路径。

当前系统最准确的定位是：

> 一套能够对稳定、周期、单通道输入进行间歇快照分析，并重建双通道输出的专用平台。

它距离通用备赛平台主要还差：

1. 启动与异常后的帧边界可信；
2. 快照/连续/触发模式的明确划分；
3. 通用测量算法、校准和物理单位；
4. PGA、比较器、保护或第二 ADC 等模拟接口；
5. 板级输入时序、长时间运行和误差记录；
6. 与正式赛题方向对应的一个深度能力分支。

如果只能选择一条近期路线，建议按以下顺序投入：

> 启动帧对齐 → 通用 DC/RMS/Vpp/频率 → 校准与单位 → 串口命令 → 自动量程前端或 IQ 微弱信号分支 → 长时间回环验证。

这条路线不会破坏当前专用识别成果，同时能最大程度覆盖给定材料预测的 2026 年信号类母题。
