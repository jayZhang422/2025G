# 现有工程架构与 PS 使用指南

> 本文是当前工程结构、公共 API、改题方法和架构评价的唯一入口。  
> 当前源码事实优先于本文；硬件固定参数以 `hardware_config.h` 和 BSP `xparameters.h` 为准。

## 1. 当前工程是什么

当前工程最成熟的业务是：

> 采集一路 ADC 信号，识别两个正弦/三角波分量，再通过双路 DDS/AD9767 重建输出。

它已经具备较清楚的五层结构：

```text
identification_main.c
  → signal_separator_task.c
  → signal_separator_run()        题目状态机
  → signal_api                    公共硬件编排
  → signal_analysis              旧题专用算法
  → DMA / IQ / DDS / 按键 / monitor 驱动
  → PL 寄存器和 AXIS 数据通路
```

它不是切换一个 profile 就能运行 AM/FM/FSK 的通用信号平台。预留的 mode/profile 只表示计划位置，不表示算法已经存在。

## 2. 当前三条硬件数据路径

### 2.1 ADC 原始采集

```text
AD9226 12 bit
 → 相移采样时钟寄存
 → 双时钟 FIFO
 → 16 bit 高位对齐 AXIS
 → 每 4096 beat 一个 TLAST
 → AXI DMA S2MM
 → DDR
 → PS Cache 管理
```

当前工程实际采样率约为 5.12006 MSPS：

```text
4096 samples = 8192 bytes ≈ 0.8 ms
FFT bin width ≈ 1250 Hz
```

AD9226 器件最高支持 65 MSPS，但当前 PLL、XDC 和板级输入时序并未因此自动在 65 MSPS 闭合。提高采样率必须重新验证时钟、输入延时、FIFO、DMA 数据率和算法配置。

### 2.2 PL 窗口 IQ

```text
ADC raw/valid
 → 32-bit phase DDS sin/cos
 → I/Q 乘法
 → 48-bit 窗口积分
 → AXI-Lite
 → PS 幅值和相位
```

它适合：

- 已知频率的幅相测量；
- 微弱单音积分；
- 候选频点确认；
- 少量频点扫描。

它不输出逐点 I/Q，因此不能直接恢复 AM 包络、FM 瞬时频率、FSK 跳频或 PSK 相位跳变。

### 2.3 DDS/DA 输出

```text
PS AXI BRAM
 → shadow registers
 → COMMIT_SEQ 原子提交
 → A/B 独立 DDS
 → 正弦/三角 ROM
 → 幅度缩放和饱和
 → 双路 AD9767
```

双路 AD9767 最高 275 MSPS，当前限制主要是 PL 只提供已有 DDS/ROM 波形，而不是 DA 器件吞吐量。

## 3. PS/PL 分工评价

### 应保留

- ADC、CDC、固定节拍 DDS 和窄带积分放 PL；
- FFT、分类、状态机、开方和反三角放 PS；
- 单一 FreeRTOS 应用任务拥有 DMA、DDS、按键和寄存器；
- DMA/Cache 顺序集中在公共函数；
- 大缓冲区静态分配，不放任务栈、不使用动态内存；
- 旧双分量算法作为专用模式隔离保留；
- 统一错误码、FIFO monitor、DMA 状态和构建标签继续保留；
- 继续使用 C，不为架构观感整体迁移 C++。

### 当前问题

- `signal_api` 名字较通用，但初始化和分析仍绑定旧题；
- `signal_api_init()` 固定初始化 DMA、FFT、按键、DDS 和 IQ，模式之间存在失败耦合；
- `signal_identify_components()` 固定调用旧 `signal_analyze_frame()`；
- 当前 Simple DMA 是单次轮询快照，不适合连续调制；
- 4096 点原始 FFT 的 0.8 ms 窗口不满足 1 kHz 调制观察；
- 窗口 IQ 只有标量结果，不是连续复基带；
- 原始 FIFO blocked/reset-busy 只记录质量标志，没有在所有模式中统一拒绝；
- 物理单位、ADC/IQ/DAC 校准和统一硬件构建 ID 仍不完整。

这些问题应在第二个真实业务出现时按需要处理，不建立插件系统或万能结果结构。

## 4. 当前程序入口

```text
main()
 → xTaskCreate(signal_separator_task)
 → signal_separator_task()
 → signal_separator_run()
```

`signal_separator_run()` 表达一条完整业务流程：

```text
初始化
 → ARMED 等待启动
 → 启动帧对齐
 → LOCKING 重复采集和识别
 → 多帧确认
 → DDS 原子提交
 → RUNNING 相位调整/复位
```

函数较长不等于必须重构。它仍然只负责一条清楚的题目状态机，不应继续吸收新的 FFT、解调和寄存器细节。

## 5. 三分钟使用统一 API

### 5.1 头文件

```c
#include "User/include/signal_api.h"
```

### 5.2 初始化

```c
signal_api_t api;
const signal_profile_t *profile = signal_profile_default();

if (signal_api_init(&api, profile) != SIGNAL_OK) {
    return XST_FAILURE;
}
```

`signal_api_t` 保存：

- DMA 实例；
- 4096 点 CMSIS FFT 配置；
- IQ、DDS、按键上下文；
- 当前 profile/mode；
- 错误、帧数和 monitor 快照。

### 5.3 一次快照测量

```c
signal_frame_t frame;
signal_analysis_result_t result;

if (signal_align_capture(&api) != SIGNAL_OK) {
    return XST_FAILURE;
}

if (signal_capture(&api, &frame) != SIGNAL_OK) {
    (void)signal_recover(&api);
    return XST_FAILURE;
}

if (signal_identify_components(&api, &frame, &result) != SIGNAL_OK) {
    return XST_FAILURE;
}
```

调用规则：

- 每次新的正式测量开始前对齐一次；
- 不要每帧都重新对齐；
- `frame.samples` 指向共享 DMA 缓冲，下一次采集会覆盖；
- 必须在下一次 `signal_capture()` 前处理完当前帧；
- 不要在业务文件复制 Cache flush/invalidate 和 DMA reset 逻辑。

## 6. 常用公共函数

| 函数 | 作用 | 边界 |
| --- | --- | --- |
| `signal_api_init()` | 初始化当前公共硬件和 FFT | 仍按旧题 profile 校验，初始化较“一锅端” |
| `signal_api_set_profile()` | 切换完整配置 | 不自动切换算法，不隐式复位硬件 |
| `signal_align_capture()` | reset S2MM 并丢弃到下一 `TLAST` | 一轮正式测量前调用一次 |
| `signal_capture()` | Cache、DMA、monitor、帧描述符 | 当前原始帧固定 8192 字节 |
| `signal_recover()` | 重新建立采集边界 | 当前主要等价于重新对齐 |
| `signal_identify_components()` | 旧双分量识别 | 固定调用旧专用算法 |
| `signal_iq_measure()` | 测一个已知频点的窗口幅相 | 不是连续 IQ 流 |
| `signal_dds_build_pair()` | 从旧识别结果构造双 DDS | 不适合伪造新题结果调用 |
| `signal_dds_apply()` | 原子提交双 DDS | 保留 COMMIT 语义 |
| `signal_dds_stop()` | 输出回中点 | 应用复位时使用 |
| `signal_api_get_status()` | 取得计数和 monitor 快照 | 用于诊断，不替代帧内元数据 |
| `signal_api_print_status()` | 打印 DMA/FIFO 状态 | 调试使用 |

## 7. 配置放在哪里

### `hardware_config.h`

只放硬件契约：

- 当前 ADC 采样率；
- 4096 点原始帧；
- DMA 设备 ID；
- IQ/DDS/monitor/按键的 `XPAR_*` 映射；
- DMA 缓冲字节数。

硬件地址必须从 BSP `xparameters.h` 获取，禁止写死数值。

### `algorithm_config.h`

只放算法结构常量：

- FFT 长度；
- 窗函数；
- 谐波阶数；
- 峰值候选数量；
- 旧算法必须保持的结构参数。

### `signal_profiles.c/.h`

放题目级参数：

- 搜索频带和频率栅格；
- 锁定容差和残差；
- 连续确认帧数和超时；
- 允许的波形类型；
- DDS 幅度、相位和业务策略。

未来 AM/ASK/FSK/FM profile 仍是占位。没有真实算法前，不填假值绕过旧题校验。

## 8. 改题时怎么决定修改位置

### 只改参数

修改或新增 profile，不复制算法和状态机。

### 算法相同、流程稍变

修改对应 app/run 状态机，只调用公共 API。

### 采集相同、算法不同

新增独立算法模块：

```c
int xxx_init(xxx_t *context, const xxx_config_t *config);
void xxx_reset(xxx_t *context);
int xxx_process(xxx_t *context,
                const signal_frame_t *frame,
                xxx_result_t *result);
```

职责规则：

- 算法不读取按键；
- 算法不调用 `xil_printf()`；
- 算法不访问 DDS 和 DMA；
- 配置、运行状态、结果分开；
- 如果算法无跨帧状态，不创建空 context；
- 新算法至少有一个不接硬件的合成样本自测。

### 整套流程不同

新增独立 `xxx_app.c/.h` 和 `xxx_run()`，复用公共硬件层。不要同时启动两个任务访问同一个 DMA/DDS。

## 9. frame、结果和生命周期

```text
signal_profile_t          静态题目参数
signal_api_t              公共硬件长期上下文
signal_frame_t            一次 DMA 帧视图
signal_analysis_result_t  旧双分量算法结果
signal_dds_pair_t         双 DDS 提交命令
signal_status_t           公共状态和计数
```

不要把 AM/FM/FSK 字段塞入 `signal_analysis_result_t`；每个真实算法定义符合自身语义的结果结构。

## 10. DMA、Cache 和帧质量

当前顺序必须保持：

```text
采集前 monitor
 → DCache Flush
 → DMA S2MM
 → DCache Invalidate
 → 采集后 monitor
 → 检查实际长度
```

当前短帧会被拒绝。FIFO blocked/reset-busy 只设置质量标志；连续解调模式需要更严格的独立规则，因为缺一个样本就可能破坏相位和符号定时。

SG DMA 和 DDC 的具体规格见 `02_23D题方案与DDC实施计划.md`。

## 11. 错误处理

原则：错误码描述第一失败点，业务层只打印一次主要错误。

典型流程：

```c
signal_error_t error = signal_capture(&api, &frame);

if (error != SIGNAL_OK) {
    xil_printf("capture failed: %s\r\n", signal_error_string(error));
    signal_api_print_status(&api, "capture failed");
    (void)signal_recover(&api);
}
```

快速定位：

| 现象 | 第一检查点 | 第二检查点 |
| --- | --- | --- |
| ADC 不变化 | min/max/change | ADC 时钟和 valid |
| DMA 超时 | DMA 状态 | AXIS valid/ready/TLAST |
| 短帧 | 实际 BTT | 帧对齐和 FIFO 状态 |
| FFT 无候选 | ADC 幅度/饱和 | 搜索频带和 profile |
| IQ 异常 | PINC、样本数 | 输入频率和校准 |
| DDS 无输出 | COMMIT 序号 | BRAM 快照和 RUN |

## 12. 编译和新增文件

- 修改已有 `.c/.h` 后正常 Refresh/Build；
- 新增 `.c` 后让 Vitis 重新扫描源文件；
- 不手改生成的 `Debug/*.mk`；
- 优化等级通过 `.cproject` 配置并重新生成；
- 确认实际编译命令包含预期的 `-O2`；
- 修改 PL 后必须重新导出 XSA、更新 platform/BSP，再编译 ELF。

## 13. 最短检查表

### 只改参数

- [ ] 选择正确 profile；
- [ ] 只修改 profile 真实参数；
- [ ] profile 校验通过；
- [ ] UART 打印 profile 名正确；
- [ ] `-O2` 构建通过。

### 新增算法

- [ ] 独立算法文件；
- [ ] 明确输入、输出、单位和失败条件；
- [ ] 不访问硬件；
- [ ] 有合成样本自测；
- [ ] 应用层只做流程编排。

### 改采集

- [ ] 保持 Cache 顺序；
- [ ] 核对 AXIS 宽度、BTT 和 TLAST；
- [ ] 记录 monitor/overflow；
- [ ] 不用旧原始 FIFO blocked 误判新 DDC 流；
- [ ] PL、XSA、BSP、PS 同步更新。

## 14. 不建议做的事

- 不把所有新算法塞进 `signal_analysis.c`；
- 不把 `signal_api` 扩成万能大总管；
- 不提前设计插件、回调注册表或动态对象；
- 不复制 DMA/Cache 驱动做一个新题专用版本；
- 不因文件长就拆出无业务意义的层；
- 不整体迁移 C++；
- 不用 profile 占位假装算法已经实现。
