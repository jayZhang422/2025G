## 1. 总结结论

这套代码的核心思路是正确且有较高复用价值的：

```text
16384 个 AD9226 原始样本，Fs=5.120000 MSPS
 -> PS 端 193 taps 低通 FIR，抽取 4
 -> 4096 点，Fs=1.280000 MSPS，bin=312.5 Hz
 -> 去直流、真 RMS
 -> Hann 窗 + 4096 点 RFFT 搜峰
 -> 三点对数抛物线频率插值
 -> 正弦/余弦投影求各分量幅值
 -> 最多 3 个周期分量重建
 -> Upp、基频、频谱分量、1/3 周期波形
```

用户提供的新板测截图中，200/250 mVpp 单正弦的 Upp 误差为约
`-1.22~+0.92 mV`，频率误差为 `0~1 Hz`，说明当前 C 算法在这些干净单音、
整 FFT bin 测试点上表现优秀。

但不能把整个工程直接替换进当前项目，原因是两边硬件/软件契约不同：

| 项目 | 队友仓库 | 当前 25G 工程 |
| --- | --- | --- |
| ADC 标称采样率 | `5.120000 MHz` | `5.120060 MHz`，实现值约 `5.1200565 MHz` |
| DMA 输入数据 | 16384 点 ADC raw，高 12 位有效 | 4096 点 FIR 后 `signed int16` |
| 数字 FIR | PS 端 193 taps、抽 4 | PL 端 39 taps、抽 3 |
| 分析采样率 | `1.280000 MHz` | `1.706686667 MHz` 标称 |
| FFT 点数 | 4096 | 4096 |
| FFT bin | `312.5 Hz` | `416.67155 Hz` |
| DMA 模式 | Simple S2MM | SG S2MM |

因此最终建议是：

1. 保留当前已经实现的 PL `/3` FIR、4096 点 TLAST 和 SG DMA 契约。
2. 不移植队友的 raw ADC 解码、PS FIR `/4`、16384 点缓冲和 Simple DMA 驱动。
3. 复用其“FFT 搜峰、频率细化、幅相估计、周期模型重建 Upp”的算法思路。
4. 当前工程已经有 CMSIS 4096 点 RFFT，应继续使用 CMSIS，不必再复制一套自写 radix-2 FFT。
5. 幅值部分优先采用 Python 参考模型的多分量联合最小二乘，而不是板上 C 当前的逐分量独立投影。
6. 最终算法必须加入当前完整模拟链的频率相关幅相校准，不能继续使用 AD9226 手册标称换算。

## 2. 仓库实际包含的 PL 逻辑

“没有写 PL 端 IP 核”并不准确。仓库没有在 PL 中实现 FIR/FFT，但包含完整的 ADC
采集、跨时钟、AXIS、DMA 和重建脚本。

### 2.1 PL 数据流

```text
50 MHz 板载时钟
 -> Clocking Wizard
    -> 5.120 MHz ADC 驱动时钟
    -> 同频、约 7.031 ns 延迟的 ADC 采样时钟
 -> adc_capture_axis
    -> 12 bit ADC 数据寄存
    -> XPM asynchronous FIFO
    -> 16 bit AXIS，高位对齐 {adc[11:0], 4'b0}
    -> 每次 DMA 请求采集 16384 点
    -> 第 16384 个握手产生 TLAST
 -> AXI DMA Simple S2MM
 -> PS DDR
```

`scripts/create_vivado_project.tcl`可重建以下 IP/模块：

| 类型 | 实现 |
| --- | --- |
| Zynq PS | `processing_system7:5.5` |
| DMA | `axi_dma:7.1`，仅 S2MM，关闭 SG，16 bit AXIS/64 bit HP |
| PS 控制互连 | `axi_interconnect:2.1` |
| HP 数据互连 | `smartconnect:1.0` |
| 复位 | `proc_sys_reset:5.0` |
| ADC 时钟 | 仓库内 `adc_clock_wizard.xci` |
| 跨时钟 FIFO | `adc_capture_axis.sv`中的 `xpm_fifo_async` |
| CDC | `xpm_cdc_async_rst`和`xpm_cdc_single` |
| 被动诊断 | `ad_fifo_monitor_axi.v`，记录写入、AXIS、帧、阻塞和复位状态 |

这个 PL 的特点是“按 DMA 请求采一帧”，不是连续流。PS 每次传输前复位 S2MM，
利用 `TREADY` 的低到高变化触发下一次采集。该做法已经出现过帧泄漏、第二帧超时、
FIR 历史跨非连续帧污染等问题，后续通过 PL 请求门控、每帧 DMA 复位和测量前 FIR
重新初始化修正。

它与当前工程的 SG DMA 连续接收策略不同，不应直接混用驱动或帧对齐代码。

## 4. 板上 C 核心算法

### 4.1 ADC 解码、单位换算和削顶检查

每个 DMA word 先右移 4 位得到 12 bit ADC 码：

```text
code[n] = raw_high_aligned[n] >> 4
x_mV[n] = (code[n] - adc_zero_code) * adc_millivolts_per_code
```

只有 `code==0`或`code==4095`才计为 ADC 削顶。这一检查适用于队友 raw ADC 数据，
不适用于当前工程 FIR 后的 signed 16 bit 数据。

### 4.2 193 taps Kaiser 低通和抽 4

启动时用单精度浮点生成系数：

```text
h[k] = (2fc/Fs) * sinc((2fc/Fs) * (k-96)) * Kaiser(k, beta)
```

随后将全部系数除以系数和，使直流增益为 1。FIR 使用 193 点循环历史缓冲，
每输入 4 点计算一次完整 193 taps 点积：

```text
16384 input -> 4096 output
每帧乘加数 = 4096 * 193 = 790,528
```

理论群延迟为 96 个原始采样，即：

```text
96 / 5.12 MHz = 18.75 us
= 24 个抽取后样本
```

本次重新运行滤波器测试得到：

```text
0~500 kHz:       -0.00684 ~ +0.00828 dB
600 kHz 处:      -126.34 dB
600 kHz 后最差:  -59.87 dB
1 MHz 处:        -78.90 dB
```

这些是系数数学频响，不等于“完整模拟前端 + ADC + 数字 FIR”的板级抑制结果。

### 4.3 去直流与真 RMS

抽取后先计算 4096 点均值，再去均值：

```text
mean = sum(x[n]) / N
y[n] = x[n] - mean
Urms = sqrt(sum(y[n]^2) / N)
```

因此这里的 RMS 是“数字低通后、去直流后的交流真 RMS”，包含带内噪声、毛刺和
未被模型选中的残差。

### 4.4 Hann 窗、RFFT 和单边峰值谱

FFT 搜峰前使用对称 Hann 窗：

```text
w[n] = 0.5 - 0.5*cos(2*pi*n/(N-1))
z[n] = y[n] * w[n]
```

单边峰值幅度谱按窗函数 coherent gain 修正：

```text
M[k] = 2*abs(X[k]) / sum(w),  1 <= k < N/2
```

DC 与 Nyquist bin 不乘 2。

FFT 后端是自写的 4096 点单精度 radix-2 DIT 复数 FFT：

- 输入先做 12 bit bit-reversal；
- 12 级蝶形，共 24,576 个复数蝶形；
- 旋转因子递推，每 64 次重新归一化；
- 最后包装成 RFFT 格式；
- 实际仍按完整复数数组计算，并非半运算量的专用实数 FFT。

当前工程已经使用 CMSIS `arm_rfft_fast_f32`，没有必要为复用算法而换成该自写 FFT。

### 4.5 候选谱峰选择

仅在 10~500 kHz 内找局部极大值，保留幅值最大的 12 个候选。最终门限为：

```text
threshold = max(1 mVpeak, strongest_peak * 2%)
```

最多选择 3 个峰，任意两个入选峰必须相隔大于 3 bins。

注意：bin 虽然是 312.5 Hz，但保护规则意味着两个分量至少要相隔 4 bins，约
1.25 kHz，才能同时入选。频率栅格满足 500 Hz，不等于能分离相距 500 Hz 的两条谱线。

### 4.6 频率细化

板上 C 对峰值 bin 及左右 bin 的幅度取对数，再做三点抛物线插值：

```text
L = ln(M[k-1])
C = ln(M[k])
R = ln(M[k+1])

delta = 0.5*(L-R)/(L-2*C+R)
delta = clamp(delta, -0.5, 0.5)
f = (k+delta) * bin_width
```

这是成熟且便宜的频率细化方法。用户新截图中的 50、150、250 kHz 分别恰好是
`160、480、800`个 312.5 Hz bin，因此 `0~1 Hz`结果主要证明整 bin 单音性能，
不能单独证明非整 bin 精度。

### 4.7 板上 C 的分量幅值估计

对每个细化后的频率，在未加窗、已去直流的 4096 点数据上独立投影：

```text
a_i = 2/N * sum(y[n] * sin(2*pi*f_i*n/Fs))
b_i = 2/N * sum(y[n] * cos(2*pi*f_i*n/Fs))
Apeak_i = sqrt(a_i^2 + b_i^2)
```

内部保留了正弦和余弦系数，所以理论上可以计算相位：

```text
phase_i = atan2(b_i, a_i)
```

但公开结果结构没有相位字段，也没有补偿 FIR 群延迟、ADC 极性或采集起点。

逐分量投影默认各基函数近似正交。非整 bin、多分量互相接近或频率估计有偏差时，
会发生串扰；Python 的联合最小二乘更稳健。

### 4.8 Upp 的周期模型重建

旧版本直接使用滤波样本的`max-min`，容易被单点毛刺破坏。当前 C 保留最多 3 个
分量的正弦/余弦投影，在 4096 个分析时刻重建周期信号：

```text
y_model[n] = sum_i(a_i*sin(w_i*n) + b_i*cos(w_i*n))
Upp = max(y_model) - min(y_model)
```

这一改动是板测精度显著改善的主要原因。它能抑制非周期毛刺和随机噪声，但也会
忽略未被选中的真实弱分量，因此 Upp 与 RMS 当前不是基于同一个对象：

- Upp：最多 3 个已选周期分量的模型；
- RMS：全部滤波后数据，包括噪声和未拟合残差。

### 4.9 基频与 1/3 周期波形

分量按频率升序排列，最低的已选频率直接作为`fundamental_hz`。代码没有检查其余
分量是否为该频率的整数倍谐波，也没有在基波很弱时专门保护基波。

波形显示不使用上述周期模型，而是在实际滤波数据中寻找第一个可容纳完整区间的
上升过零点，然后对 1 或 3 个基频周期做线性插值，输出 640 点。

在 500 kHz 时，`1.28 MSPS`只有 2.56 个真实样本/周期。插值到 640 点不会增加
新信息，波形可稳定但细节有限。当前 `/3` 链路约 3.41 点/周期，仍建议显示时直接
根据拟合后的谐波模型高分辨率重建。

## 5. Python 参考模型不等于板上 C 实现

仓库的 Python 模型比当前板上 C 算法更强，不能把 Python 测试通过直接解释为 C
已经实现同等能力。

| 环节 | Python 参考模型 | 板上 C |
| --- | --- | --- |
| 数值精度 | `float64` | `float32` |
| FIR | FFT 循环卷积，按群延迟取样 | 因果状态 FIR，正式帧从零状态启动 |
| 初始频率 | Hann FFT + 对数抛物线 | 相同 |
| 二次频率搜索 | 正负 1 bin 内再搜索 33 个 DFT 候选 | 没有 |
| 多分量幅值 | 所有 sin/cos 列联合 `lstsq` | 每个分量独立投影 |
| 相位输出 | 内部可得但结果未公开 | 内部可得但结果未公开 |

若迁移到当前工程，应优先保留 C 的低成本搜峰和抛物线插值，同时将最终 1~3 个
分量放入一个小型联合最小二乘求解。最多 6 个未知量，计算规模远小于 FIR 和 FFT，
没有必要牺牲稳健性。

## 6. 运行时间与内存

核心计算量约为：

| 环节 | 规模 |
| --- | ---: |
| PS FIR | 790,528 次乘加/帧 |
| 4096 FFT | 24,576 个复数蝶形 |
| 带内峰扫描 | 约 1,569 bins |
| 幅值投影 | 最多 `3*4096` 点 |
| Upp 重建 | 最多 `3*4096` 点 |

```text

FIR 系数/历史             约   1.5 KiB
```

## 8. 已确认的局限和风险

### 8.1 采样率和帧长被写死

板上 C 配置和 FIR 均固定`5,120,000 Hz`，并拒绝与该值相差超过`0.5 Hz`的
配置。当前实际值`5,120,060 Hz`若如实传入，会直接返回参数错误。

如果仍谎报为`5,120,000 Hz`，比例误差本身不大，500 kHz 处约造成`-5.86 Hz`
标尺误差，但这仍是错误的数据契约，不能作为正式实现。

### 8.2 不能直接识别“基波 + 谐波”关系

代码只是取阈值以上的最多 3 个峰并按频率排序，最低频即基频。它没有：

- 检查频率是否接近整数倍；
- 在基波弱于谐波时专门保护基波；
- 抑制偶然的带内杂散峰；
- 区分 1、2、3 次或更高次谐波。

若真实基波低于`1 mVpeak`或低于最强峰的 2%，就可能被丢弃并把某个谐波误报为
基频。题面没有给各分量最小幅度，因此这个边界必须补测。

### 8.3 C 幅值估计弱于 Python 联合拟合

逐分量投影在分量不正交时存在串扰；当前 API 也没有输出相位。对于完整模拟滤波器
造成的频率相关相移，只有幅值没有相位不足以准确重建输入端多谐波 Upp。

### 8.4 正式帧仍从 FIR 零状态启动

主程序先分析一帧“预热”，但两次 DMA 帧并不连续，所以随后又重新初始化 FIR。
正式测量帧仍包含前 24 个抽取样本的零状态瞬态，约占 4096 点的`0.586%`。
Hann 窗会减轻其对搜峰的影响，但 RMS 使用未加窗全帧，Python 循环卷积模型也没有
覆盖这一实际边界。

### 8.5 模拟抗混叠仍不可省略

PS FIR 能衰减采样后仍位于阻带的 1 MHz 分量，但无法恢复 ADC 采样前已经折叠进
0~500 kHz 的高频噪声。任何采用约 5.12 MSPS 的方案仍需要模拟抗混叠滤波器；
队友的干净信号源测试不能证明无滤波器时面对现场高频干扰仍可靠。

### 8.6 应用还不是完整参赛程序

当前`main.c`只执行一次：初始化、预热帧、测量帧、计算、生成两组波形数组并打印
串口日志，然后退出。HMI 只完成 UART 初始化，没有发送实际波形/频谱/数值，也没有
按键主循环。因此它是很好的板级算法 bring-up，不是可以直接交付的完整应用。

## 9. 接入当前 `/3` PL 链路的建议

当前工程的固定输入应定义为：

```text
DMA frame:       4096 samples
sample type:     signed int16，PL FIR 输出码值
sample rate:     5,120,060 / 3 = 1,706,686.667 Hz nominal
frame bytes:     8192
FFT bins:        4096
bin width:       416.67155 Hz
Nyquist:         853.34333 kHz
```

当前`hardware_config.h`仍把`APP_SAMPLE_RATE_HZ`写成 raw ADC 的`5120060.0f`，
而 DMA 帧实际已是 PL FIR 抽 3 后数据。正式算法接入时必须把“ADC 时钟”和“分析
采样率”拆成两个明确常数，不能继续混用。

### 9.1 应保留/复用

- 去直流和全帧真 RMS 的计算框架；
- Hann 窗仅用于频谱搜索；
- 单边谱 coherent-gain 修正；
- 局部峰搜索和候选排序；
- 三点对数抛物线频率细化；
- 最多 3 个周期分量的模型；
- 用模型计算 Upp，避免原始`max-min`；
- 从模型生成 1/3 周期显示数据；
- 帧质量、DMA 长度、FIFO 阻塞和削顶拒绝逻辑。

### 9.2 不应直接复用

- `uint16 >> 4` raw ADC 解码；
- `adc_zero_code=2048`和`-2.44140625 mV/code`的手册标称换算；
- 16384 点 DMA 缓冲假设；
- PS 193 taps FIR 和抽 4；
- `Fs==5120000+/-0.5 Hz`硬检查；
- Simple DMA 每帧复位/`TREADY`触发采集逻辑；
- 自写 radix-2 FFT，当前 CMSIS 已覆盖；
- 把最低的三个强峰直接当成基波/谐波的规则。

### 9.3 推荐的当前 PS 算法顺序

```text
4096 x signed int16 PL-FIR samples
 -> 检查 DMA 长度、FIFO/停顿、ADC/FIR 削顶状态
 -> 使用端到端标定将 code 转为输入端量纲
 -> 去直流
 -> Hann + CMSIS 4096 RFFT
 -> 10~500 kHz 候选峰
 -> 抛物线或小范围投影频率细化
 -> 依据整数倍关系选择基波和 1~2 个谐波
 -> 对全部候选频率做联合 sin/cos 最小二乘
 -> 用频率相关复增益表校正每个分量的幅值和相位
 -> 高分辨率重建输入端周期波形
 -> Upp、Urms、基频、各峰值幅度、1/3 周期波形、正频谱显示
```

真 RMS 最终建议由校准后的谐波模型计算：

```text
Urms = sqrt(sum_i(Apeak_i^2 / 2))
```

该式要求分量是不同整数谐波且按完整周期定义；也可对高分辨率重建的一个完整基波
周期直接积分求 RMS。这样 Upp、RMS 和频谱幅值来自同一套校准后模型，避免当前
“Upp 与 RMS 对象不同”的问题。

## 10. 采用前最小验收矩阵

### 10.1 主机合成测试

- 幅值：50、100、200、250 mVpp；
- 基频：10、50、150、250、400、500 kHz；
- 非整 bin：10.5、83.7、123.4、499.5 kHz；
- 基波 + 1 个谐波、基波 + 2 个谐波；
- 基波弱于谐波、接近检测阈值；
- 多组相位，尤其会改变总 Upp 的组合；
- 叠加单点毛刺、白噪声、直流偏置和 1 MHz 干扰；
- 对照 Upp、真 RMS、各分量峰值、频率和相位。

### 10.2 同一最终硬件链板测

```text
信号源
 -> 51 Ohm 终接下的 LC
 -> 约 30 倍放大器和 51/50 Ohm 匹配
 -> AD9226
 -> 当前 PL FIR /3
 -> 当前 SG DMA
 -> 新 PS 算法
```

至少验证：

- 50/100/200/250 mVpp；
- 10~500 kHz 代表点和非整 bin 点；
- 1~3 个分量及不同相位；
- `ub + 200 mVpp、>=1 MHz`干扰；
- 最大组合下放大器/ADC不削顶；
- 连续重复帧、FIFO阻塞/满溢、短帧拒绝；
- 每项 Upp、RMS、频谱幅值绝对误差不超过 5 mV；
- 基频误差不超过 1 kHz；
- 从启动操作到屏幕稳定结果不超过 2 s。

每轮板测应保存：输入设置、实际接线、bit/XSA/ELF 哈希、原始串口日志、截图、
重复次数和统计值，避免再次出现截图与汇总文本不一致。

## 11. 最终复用判断

队友代码值得复用，但复用单位应是“算法思想和少量纯算法函数”，不是整套 PL/PS
工程。它最有价值的部分是：

1. 证明 12 bit、10 Vpp ADC 在稳定单音和长帧拟合下可以获得亚 LSB 的参数估计；
2. 证明直接`max-min`不可靠，周期分量重建能显著改善 Upp；
3. 给出了可运行的 Hann 搜峰、频率插值、投影和波形整理基线；
4. 给出了约 23 ms 的 Cortex-A9 实际运行量级和帧完整性诊断方法。

当前最稳妥的工程路线仍是冻结 PL `/3`链路，在现有 PS/CMSIS 框架中吸收上述算法，
同时补上联合最小二乘、谐波关系判断、频率相关幅相校准、连续采集质量检查和完整
HMI 主循环。
