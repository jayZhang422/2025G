# PS 自研函数与结构体使用手册

## 1. 当前没有统一对象

Doc 中建议的 `signal_api_t` 尚未实现。当前状态分别保存在以下对象中：

| 对象 | 定义位置 | 谁创建/初始化 | 保存什么 |
| --- | --- | --- | --- |
| `XAxiDma` | Xilinx 驱动 | `signal_separator_app.c` 的静态对象；`dma_init_s2mm()` 初始化 | DMA 驱动状态 |
| `arm_rfft_fast_instance_f32` | CMSIS-DSP | 应用静态对象；`arm_rfft_fast_init_f32()` 初始化 | 4096 点 RFFT 配置 |
| `iq_demodulator_t` | `iq_demodulator.h` | 应用静态对象；`iq_demodulator_init()` 绑定基址 | IQ IP 的 AXI-Lite 基址 |
| `dds_control_t` | `dds_control.h` | `signal_separator_run()` 栈对象；`dds_control_init()` 初始化 | DDS BRAM 基址和下一提交序号 |
| `button_input_t` | `button_input.h` | `signal_separator_run()` 栈对象；`button_input_init()` 初始化 | PS GPIO 实例和按键状态 |
| `signal_profile_t` | `signal_profiles.h` | 由 `signal_profile_default/get()` 返回只读指针 | 题目频带、栅格、确认帧数 |
| `signal_analysis_result_t` | `signal_processing.h` | 调用者创建栈对象，算法填充 | A/B 分量和联合残差 |
| `iq_measurement_t` | `iq_demodulator.h` | 调用者创建栈对象，驱动填充 | I/Q 和、样本数、结果序号、实际 PINC |
| `fifo_monitor_snapshot_t` | `fifo_monitor.h` | 调用者创建栈对象，驱动填充 | FIFO/AXIS 累计计数器快照 |

这些结构体都不是动态分配对象。惯用方式是“调用者声明变量 -> 调用 init ->
把地址传给后续函数”。`signal_profile_t` 是例外：调用者只保存只读指针，
不能修改静态 profile。

## 2. 应用入口

| 函数 | 作用 |
| --- | --- |
| `signal_separator_task(void *)` | FreeRTOS 任务入口，只调用业务入口。 |
| `signal_separator_run(void)` | 当前唯一完整业务入口，内部运行 `ARMED -> LOCKING -> RUNNING`。 |

如果只是运行现有题目，不需要在别处手动组合各结构体；`main()` 已经创建任务，
任务会进入 `signal_separator_run()`。

## 3. 读取 profile

```c
const signal_profile_t *profile = signal_profile_default();

if (profile == NULL || profile->confirm_frames == 0U) {
    /* 配置无效，不能进入分析。 */
}
```

- `signal_profile_get(id)`：按 ID 返回只读 profile，越界返回 `NULL`。
- `signal_profile_default()`：当前固定返回 `PROFILE_OLD_SEPARATOR`。
- `signal_profile_count()`：返回登记数量；除旧分离模式外，其余条目目前只是零值占位，不能直接运行。

## 4. DMA 与 FFT 分析

DMA 缓冲区 `g_adc_raw_buffer` 已由 `app_buffers.c` 静态分配在
`.dma_buffer`，不要在任务栈上再建 4096 点数组。

```c
XAxiDma dma;
arm_rfft_fast_instance_f32 fft;
signal_analysis_result_t result;
const signal_profile_t *profile = signal_profile_default();

dma_init_s2mm(&dma, APP_DMA_RX_DEV_ID);
arm_rfft_fast_init_f32(&fft, APP_FFT_LEN);

Xil_DCacheFlushRange((UINTPTR)g_adc_raw_buffer, APP_RX_FRAME_BYTES);
if (dma_capture_frame(&dma, APP_DMA_RX_DEV_ID,
                      g_adc_raw_buffer, APP_RX_FRAME_BYTES) == XST_SUCCESS) {
    Xil_DCacheInvalidateRange((UINTPTR)g_adc_raw_buffer,
                              APP_RX_FRAME_BYTES);
    signal_analyze_frame(g_adc_raw_buffer, &fft,
                         g_time_domain_buffer, g_fft_input_buffer,
                         g_fft_spectrum_buffer, g_fft_magnitude_buffer,
                         g_model_buffer, profile, &result);
}
```

必须保持 `Flush -> DMA -> Invalidate -> CPU 读取` 的顺序。当前
`dma_capture_frame()` 只在 DMA 失败/超时后的下一次恢复中丢弃一帧对齐；正常
启动后的第一次正式采集没有预对齐，也没有把 monitor 前后快照绑定到该帧。

## 5. IQ 测量

```c
iq_demodulator_t iq;
iq_measurement_t result;

if (iq_demodulator_init(&iq) == XST_SUCCESS &&
    iq_demodulator_measure(&iq, 25000.0f, &result) == XST_SUCCESS) {
    /* result.i_sum / q_sum 是 48 位积分结果；sample_count 用于归一化。 */
}
```

`iq_demodulator_t` 只保存硬件基址，不保存测量结果。结果在
`iq_measurement_t` 中；`phase_increment` 是 PL 实际采用的 PINC，应以它反算
真实参考频率。当前驱动使用固定窗口，没有公共 scan/average API。

## 6. DDS 两通道原子提交

```c
dds_control_t dds;
dds_channel_config_t channel_a;
dds_channel_config_t channel_b;
signal_analysis_result_t analysis_result;

dds_control_init(&dds);
/* analysis_result 由前面的 signal_analyze_frame() 成功填充。 */
dds_control_from_component(&analysis_result.channel_a, 0.0f, &channel_a);
dds_control_from_component(&analysis_result.channel_b, 180.0f, &channel_b);
dds_control_commit(&dds, &channel_a, &channel_b, 1, 1);
```

- `dds_control_t` 必须在多次提交之间保留，不能每次临时重新初始化，否则提交序号会回到 1。
- `dds_channel_config_t` 是一次提交的值对象，包含波形、相位步进、绝对相位和幅度码。
- `dds_control_commit()` 先写 A/B 全部 shadow 字，再最后写 `COMMIT_SEQ`。
- `phase_reload=1, run=1` 启动；两个零配置通道配合 `run=0` 停止。
- `dds_control_adjust_b_phase()` 只用于运行状态下的 B 通道相位增量调整。

## 7. FIFO monitor

```c
fifo_monitor_snapshot_t snapshot;

if (fifo_monitor_init() == XST_SUCCESS &&
    fifo_monitor_snapshot(&snapshot) == XST_SUCCESS) {
    fifo_monitor_print("current", &snapshot);
}
```

快照中的计数器是累计量，不自动对应某一 DMA 帧。若要判断一帧是否可靠，
需要在采集前后各取一次快照并比较增量；当前主流程尚未这样做。

## 8. 错误返回规则

当前没有 `signal_error_t`。多数函数只返回 `XST_SUCCESS`、`XST_FAILURE`，
DMA 等待还可能内部产生 `XST_TIMEOUT`，但公共采集函数最终把失败统一返回为
`XST_FAILURE`。定位失败原因仍需结合 `[DMA]`、`[FIFO]`、`[FFT]`、`[IQ]`
和 `[DDS]` 日志。
