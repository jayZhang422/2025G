# PS 统一 API、函数与结构体使用手册

## 1. 头文件和对象所有权

模式层优先只通过以下头文件取得现有公共能力：

```c
#include "User/include/signal_api.h"
```

核心对象如下。

| 类型 | 谁创建 | 谁初始化/填充 | 生命周期与用途 |
| --- | --- | --- | --- |
| `signal_api_t` | 模式函数栈或静态区 | `signal_api_init()` | 必须贯穿一次应用运行；持有 DMA、FFT、IQ、DDS、按键、profile、计数器 |
| `const signal_profile_t *` | `signal_profile_get/default()` 返回 | 静态只读表 | 调用者只保存指针，不修改内容 |
| `signal_frame_t` | 调用者 | `signal_capture()` | 一帧描述符；`samples` 指向静态 DMA 缓冲，不拥有样本 |
| `signal_analysis_result_t` | 调用者 | `signal_identify_components()` | A/B 分量和联合残差 |
| `iq_measurement_t` | 调用者 | `signal_iq_measure()` | PL I/Q 累加结果、样本数、序号和实际 PINC |
| `signal_dds_pair_t` | 调用者 | `signal_dds_build_pair()` | 一次 A/B 原子提交配置，可继续用于运行中 B 相位微调 |
| `signal_status_t` | 调用者 | `signal_api_get_status()` | 计数器、最后 DMA 长度、monitor 前后快照和可用性 |

不要每次提交 DDS 前重新初始化 `signal_api_t`。其中的
`dds.next_commit_sequence` 必须连续递增，DMA/FFT/按键对象也需要保持。

## 2. 初始化怎么写

### 2.1 使用默认旧题 profile

```c
signal_api_t api;
const signal_profile_t *profile = signal_profile_default();
signal_error_t error;

if (!signal_profile_is_configured(profile)) {
    /* 默认 profile 数据不完整。 */
    return;
}

error = signal_api_init(&api, profile);
if (error != SIGNAL_OK) {
    xil_printf("[APP] init failed: %s\r\n",
               signal_error_string(error));
    return;
}
```

`signal_api_init()` 内部依次完成：绑定 profile、初始化 IQ、初始化并复位
S2MM DMA、初始化 4096 点 RFFT、初始化 GPIO 按键、初始化 FIFO monitor、
初始化 DDS 控制对象并原子提交停止状态。

DMA、FFT、按键或 DDS 失败是致命错误并直接返回对应错误码。IQ 和 monitor
属于补充能力，初始化失败会在 `signal_status_t` 中显示不可用，但不阻止现有
DMA+FFT+DDS 主流程。

### 2.2 初始化后检查可选能力

```c
signal_status_t status;

if (signal_api_get_status(&api, &status) == SIGNAL_OK) {
    if (!status.iq_available) {
        /* 不调用 signal_iq_measure()。 */
    }
    if (!status.monitor_available) {
        /* 仍可采集，但没有帧外计数器快照。 */
    }
}
```

## 3. profile 在哪里、怎么选、怎么改

定义和数据位于：

```text
User/config/signal_profiles.h   类型、ID、字段、波形 mask
User/config/signal_profiles.c   静态只读 profile 表
```

选择方式：

```c
const signal_profile_t *profile;

profile = signal_profile_get(PROFILE_OLD_SEPARATOR);
/* 或使用当前默认项。 */
profile = signal_profile_default();
```

运行中只允许切到已经完整配置的 profile：

```c
if (signal_api_set_profile(&api, profile) != SIGNAL_OK) {
    xil_printf("profile: %s\r\n",
               signal_error_string(signal_api_last_error(&api)));
}
```

`signal_api_set_profile()` 只切换参数，不自动清 FIFO、不重启 DMA、不停止 DDS。
通常应在 `ARMED/IDLE` 状态调用，然后在下一次采集前执行
`signal_align_capture()`。

### 3.1 当前有效字段

| 字段 | 单位/含义 | 当前谁使用 |
| --- | --- | --- |
| `mode` | 模式枚举 | API 保存当前模式 |
| `frequency_min_hz/max_hz` | FFT 搜索下限/上限，Hz | `signal_analysis.c` |
| `frequency_grid_hz` | 旧题频率栅格，Hz | 候选搜索和锁定规范化 |
| `grid_lock_tolerance_hz` | 离栅格最大允许偏差，Hz | 算法候选和应用锁定 |
| `lock_max_residual` | 归一化联合残差上限 | 应用锁定、自测 |
| `confirm_frames` | 连续一致帧数 | `signal_separator_app.c` |
| `lock_timeout_seconds` | 一次锁定超时，秒 | `signal_separator_app.c` |
| `allowed_waveforms` | 正弦/三角 bit mask | 波形组合枚举 |
| `dds_amplitude_code` | 0..8191 的 DDS 幅度码 | `signal_dds_build_pair()` |
| `initial_phase_degrees` | B 相对 A 的初值，度 | ARMED/RUNNING 状态机 |
| `phase_step_degrees` | 按键单步，度 | 相位增减按键 |
| `phase_max_degrees` | 相位选择环绕上限，度 | 相位按键逻辑 |

`expected_carrier_hz`、`expected_deviation_hz`、`expected_symbol_rate` 是将来模式的
预留字段。当前不能因为字段存在就认为对应解调算法已经实现。

### 3.2 新题参数应该改哪里

只编辑 `signal_profiles.c` 中对应条目，不修改 `dma_utils.c`、
`signal_analysis.c` 或寄存器驱动。没有真实题目参数时保持零值；
`signal_profile_is_configured()` 会拒绝不完整 profile。

## 4. 首次帧对齐与采集

### 4.1 为什么开始前要对齐

在 `ARMED` 等按键期间 ADC 仍在运行，FIFO 可能已经从某一帧中间开始积累。
因此一次新的正式测量应先调用：

```c
signal_error_t error = signal_align_capture(&api);

if (error != SIGNAL_OK) {
    xil_printf("align: %s\r\n", signal_error_string(error));
    return;
}
```

该函数复位 S2MM，并用独立静态丢弃缓冲接收到一个 `TLAST`。下一次
`signal_capture()` 才是正式帧。不要在连续确认的每一帧前调用对齐，否则会为
每帧增加一次 reset 和丢弃。

### 4.2 采集一帧

```c
signal_frame_t frame;
signal_error_t error = signal_capture(&api, &frame);

if (error != SIGNAL_OK) {
    xil_printf("capture: %s\r\n", signal_error_string(error));
    signal_api_print_status(&api, "[DMA] capture failed:");
    return;
}

/* 只有成功后才读取 frame.samples。 */
```

API 内部固定执行：

```text
monitor_before
  -> DCache Flush 静态 DMA 缓冲
  -> 提交 SG S2MM 接收 BD
  -> DMA IRQ 唤醒任务并回收完成 BD
  -> DCache Invalidate
  -> monitor_after
  -> 检查完成 BD 的实际长度
```

`signal_frame_t` 字段：

| 字段 | 含义 |
| --- | --- |
| `samples` | 指向 `g_adc_raw_buffer`；下一次采集会覆盖，不能长期保存指针内容 |
| `sample_count` | DMA 实际字节数除以 2；正常为 4096 |
| `sample_rate_hz` | 当前硬件采样率 `5120060.0f` |
| `frame_sequence` | API 成功启动以来的采集序号 |
| `quality_flags` | `SHORT`、`FIFO_BLOCKED`、`RESET_BLOCKED` bit |
| `frame_valid` | 当前只对短帧置 0；monitor blocked 标志保留给调用者观察 |

为保持当前已验证的间歇快照语义，FIFO blocked/reset 增量会记录在
`quality_flags`，但本次不会未经板测就把所有 blocked 增量一律判为无效帧。
短帧会返回 `SIGNAL_ERR_FRAME_INVALID`，不进入 FFT。

## 5. 调用现有双分量识别

```c
signal_frame_t frame;
signal_analysis_result_t result;

if (signal_capture(&api, &frame) == SIGNAL_OK &&
    signal_identify_components(&api, &frame, &result) == SIGNAL_OK) {
    xil_printf("A=%d Hz, B=%d Hz\r\n",
               (int)result.channel_a.frequency_hz,
               (int)result.channel_b.frequency_hz);
}
```

参数规则：

- `api`：已初始化对象，内部提供 FFT 实例、profile 和静态工作区；
- `frame`：必须来自成功的 `signal_capture()`，且正好 4096 点；
- `result`：调用者分配，成功后由函数完整填充；
- 返回 `SIGNAL_ERR_ANALYSIS` 表示现有算法没有找到有效双分量组合，不等于 DMA 失败。

## 6. 调用 PL IQ

```c
iq_measurement_t iq_result;
signal_error_t error;

error = signal_iq_measure(&api, 25000.0f, &iq_result);
if (error == SIGNAL_OK) {
    /* i_sum、q_sum 是积分值；sample_count 用于归一化。 */
    /* phase_increment 是 PL 实际采用的 PINC。 */
}
```

输入频率必须大于 0。IQ 用于已知频率幅相测量，不负责未知频率搜索。
当前只有单次固定窗口接口，没有 scan/average 新算法。

## 7. 构造和提交双 DDS

### 7.1 从识别结果构造

```c
signal_dds_pair_t pair;

if (signal_dds_build_pair(&api, &result, 30.0f, &pair) != SIGNAL_OK) {
    return;
}
if (signal_dds_apply(&api, &pair) != SIGNAL_OK) {
    xil_printf("dds: %s\r\n",
               signal_error_string(signal_api_last_error(&api)));
}
```

第三个参数是用户要求的 B 相对 A 初相，单位为度。API 会：

- 使用 A/B 的识别频率和波形；
- 从当前 profile 读取幅度码；
- 对 B 叠加现有硬件 180 度补偿；
- 在 B/A 为整数比时继续保持原有相位步进比例修正；
- 生成 `phase_reload=1, run=1` 的原子启动配置。

### 7.2 运行中调整 B 相位

```c
signal_dds_adjust_b_phase(&api, &pair, +5.0f);
signal_dds_adjust_b_phase(&api, &pair, -5.0f);
```

`pair` 必须是实际启动 DDS 时使用的配置。该调用走现有
`RUN | B_PHASE_ADJUST` 协议，不重载 A/B 相位。

### 7.3 停止

```c
signal_dds_stop(&api);
```

停止使用一次完整原子提交并令 PL 输出中点，不要手写 BRAM 寄存器。

## 8. 按键、状态和恢复

按键事件：

```c
if (signal_api_take_button(&api, SIGNAL_BUTTON_START)) { /* KEY1 */ }
if (signal_api_take_button(&api, SIGNAL_BUTTON_RESET)) { /* N16 */ }
if (signal_api_take_button(&api, SIGNAL_BUTTON_PHASE_INCREMENT)) { /* T17 */ }
if (signal_api_take_button(&api, SIGNAL_BUTTON_PHASE_DECREMENT)) { /* R17 */ }
```

`signal_api_take_button()` 返回消抖后的单次按压事件；
`signal_api_button_level()` 返回当前原始逻辑电平。

获取状态：

```c
signal_status_t status;

signal_api_get_status(&api, &status);
xil_printf("captures=%d align=%d dma_err=%d bad=%d last_btt=%d\r\n",
           (int)status.capture_count,
           (int)status.alignment_count,
           (int)status.dma_error_count,
           (int)status.bad_frame_count,
           (int)status.last_dma_length_bytes);
```

`signal_recover(&api)` 当前执行与启动对齐相同的 S2MM reset + 丢弃至
`TLAST`。恢复成功后再调用 `signal_capture()`。

## 9. 错误返回规则

所有公共业务函数返回 `signal_error_t`。常用错误：

| 错误 | 第一检查位置 |
| --- | --- |
| `SIGNAL_ERR_PROFILE_INVALID` | `signal_profiles.c` 是否填齐当前模式字段 |
| `SIGNAL_ERR_DMA_INIT` | BSP 设备 ID、DMA 是否为 simple S2MM-only |
| `SIGNAL_ERR_FRAME_ALIGN` | DMA 状态、FIFO/AXIS 是否能送出 `TLAST` |
| `SIGNAL_ERR_DMA_CAPTURE` | `[DMA]` 状态寄存器和 monitor beat/frame |
| `SIGNAL_ERR_FRAME_INVALID` | `last_dma_length_bytes` 是否为 8192 |
| `SIGNAL_ERR_ANALYSIS` | ADC 范围、profile 频带/栅格、双分量条件 |
| `SIGNAL_ERR_IQ_UNAVAILABLE/MEASURE` | IQ 版本、结果序号和超时 |
| `SIGNAL_ERR_DDS_COMMIT` | BRAM 快照、commit 序号和参数范围 |

任何错误都可用 `signal_error_string(error)` 转成人类可读字符串；
`signal_api_last_error(&api)` 返回该 API 对象记录的最近一次公共调用结果。

## 10. 什么时候才直接调用底层函数

新比赛模式默认不直接调用 `dma_utils`、`fifo_monitor`、`iq_demodulator`、
`dds_control`。只有在调试某个驱动本身或扩展统一 API 内部实现时，才进入
对应底层文件。这样可以保证 Cache、首次帧对齐、DDS 提交序号和错误计数不会
在不同模式中各自复制一套。
