# PS 现有双分量信号分析算法

本文只描述已经存在的 4096 点“双分量正弦/三角识别器”。本次架构整理没有
新增通用 DC/RMS/Vpp、载波检测、AM/ASK/FSK/FM 或滤波算法。

## 1. 从统一 API 调用

```c
signal_frame_t frame;
signal_analysis_result_t result;

if (signal_capture(&api, &frame) != SIGNAL_OK) {
    return;
}
if (signal_identify_components(&api, &frame, &result) != SIGNAL_OK) {
    return;
}
```

`signal_identify_components()` 只是给现有 `signal_analyze_frame()` 提供统一入口：
它从 `api` 取得 FFT 实例、当前 profile 和静态工作区，并验证 `frame` 是 4096 点
有效帧。算法数学流程没有被重写。

底层直接接口仍在 `signal_processing.h`，只建议在算法模块内部或独立算法自测
时使用，不建议新模式自行拼接五个工作区参数。

## 2. 输入和输出

输入 `signal_frame_t`：

- `samples` 指向 4096 个 16 位 DMA 字；
- 有效 AD9226 码位于高 12 位，算法右移 4 位得到 0..4095；
- `frame_valid` 必须为真，`sample_count` 必须为 4096；
- Cache Flush/Invalidate 已由 `signal_capture()` 完成。

输出 `signal_analysis_result_t`：

| 字段 | 含义 |
| --- | --- |
| `channel_a` | 较低频分量的频率、基波幅度、相位、波形 |
| `channel_b` | 较高频分量的频率、基波幅度、相位、波形 |
| `normalized_residual` | 双分量联合模型的归一化残差 |

幅度和相位仍是算法内部结果，没有 ADC 电压校准或系统时延补偿，不能直接标成
V、Vrms、dBm 或被测网络绝对相位。

## 3. 算法流程

1. `signal_prepare_adc_frame()` 取高 12 位 ADC 码、去直流，并生成 Hann 窗 FFT 输入。
2. CMSIS `arm_rfft_fast_f32()` 执行 4096 点实数 FFT。
3. `signal_compute_magnitudes()` 得到半谱模值。
4. `signal_find_candidate_peaks()` 在 profile 的频率上下限内提取局部峰。
5. `signal_refine_frequency()` 用三点抛物线插值细化 FFT bin。
6. `signal_snap_to_grid()` 按 profile 栅格和容差筛选候选。
7. `signal_build_frequency_candidates()` 加入三倍频/三分频候选，处理三角波三次谐波冲突。
8. 枚举两频率以及 profile 允许的 A/B 波形组合。
9. 对每个组合做正交投影、两轮交替残差投影和联合残差评分。
10. 返回残差最小的 A/B 组合。

三角波模型只合成奇次谐波，幅值按 `1/n^2` 衰减并交替反相，最高到
`APP_TRI_MAX_HARMONIC`。振荡器使用递推，每 64 点归一化一次，避免内层循环
逐点调用 `sinf/cosf`。

## 4. 哪些参数在 profile

当前识别和锁定相关题目参数集中在 `signal_profiles.c`：

- `frequency_min_hz`、`frequency_max_hz`；
- `frequency_grid_hz`、`grid_lock_tolerance_hz`；
- `allowed_waveforms`；
- `lock_max_residual`；
- `confirm_frames`；
- `lock_timeout_seconds`。

波形 mask 示例：

```c
.allowed_waveforms = SIGNAL_WAVEFORM_MASK_ALL
/* 或只允许正弦：SIGNAL_WAVEFORM_MASK_SINE */
```

默认 `PROFILE_OLD_SEPARATOR` 仍是 20--100 kHz、5 kHz 栅格、1000 Hz 容差、
正弦+三角、残差 0.30、连续 3 帧、18 秒超时，与整理前有效行为一致。

## 5. 哪些参数仍是算法实现常量

以下值没有被伪装成题目 profile，因为它们与当前实现结构或计算量直接相关：

- `APP_FFT_LEN`/`APP_SPEC_LEN`：与 PL 4096 点帧固定绑定；
- `APP_FFT_WINDOW`：当前 Hann 窗实现选择；
- `APP_PEAK_CANDIDATE_COUNT`：候选表固定容量；
- `APP_MIN_COMPONENT_GAP_HZ`：双分量搜索的实现约束；
- `APP_TRI_MAX_HARMONIC`：三角模型计算上限。

若正式题目需要任意非栅格频率、单分量、更多分量或其他波形，应新增独立模式
和明确算法入口，不要破坏 `PROFILE_OLD_SEPARATOR` 的专用算法。

## 6. 应用层锁定策略

`signal_separator_app.c` 在单帧算法成功后继续执行：

1. 检查 `normalized_residual <= profile->lock_max_residual`；
2. 再次按 profile 栅格规范化 A/B 频率并验证上下限；
3. 要求 A 频率小于 B；
4. 要求连续 `profile->confirm_frames` 帧的 A/B 波形和栅格频率完全一致；
5. 超过 `profile->lock_timeout_seconds` 则返回 `ARMED`；
6. 锁定后不再自动跟踪输入频率，避免噪声驱动 DDS 更新。

## 7. 自测范围

`signal_run_self_tests()` 构造五组合成帧：四种正弦/三角 A/B 组合，加一个
`fB = 3*fA` 谐波冲突用例。它验证 C 算法和默认 profile，不访问 DMA、FIFO、
IQ、DDS、RTL 或板级模拟链路。

本次验收只要求 Vitis `-O2` 编译，不把合成自测、上板、长时间运行或大规模
黄金数据回归冒充已执行验证。
