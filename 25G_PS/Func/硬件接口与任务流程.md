# PS 硬件接口与当前任务流程

## 1. 真实调用链

```text
main()
  |- xTaskCreate(signal_separator_task)
  `- vTaskStartScheduler()

signal_separator_task()
  `- signal_separator_run()
      |- 初始化 IQ、DMA、FFT、按键、FIFO monitor、DDS
      |- ARMED：等待 KEY1，DDS 保持停止
      |- LOCKING：重复 DMA 采集 + FFT 分析，连续确认 profile 指定帧数
      `- RUNNING：原子启动双 DDS，测一次 A/B IQ，处理相位键和复位键
```

工程只有 `identification_main.c` 定义 `main()`，不包含历史 `.txt/.c`
业务源文件。当前也没有 Modes 层和统一 Signal API 层；
`signal_separator_app.c` 直接调用所有驱动和算法。

## 2. 初始化顺序

`signal_separator_run()` 当前按下列顺序初始化：

1. `iq_demodulator_init(&g_iq_detector)`；失败只告警，主流程继续。
2. 校验 `signal_profile_default()` 返回的旧分离 profile。
3. 可选运行 `signal_run_self_tests()`。
4. `dma_init_s2mm()`、`arm_rfft_fast_init_f32()`、`button_input_init()`；任一失败则退出。
5. 初始化 FIFO monitor，打印一次快照并清 sticky；失败只告警。
6. `dds_control_init()`，随后提交 `run=0` 的停止快照。

这段顺序目前只存在于 `signal_separator_app.c`，还没有被包装成
`signal_api_init()`。

## 3. DMA、缓存与帧边界

一次正常采集的所有权顺序是：

```text
CPU Flush g_adc_raw_buffer
  -> XAxiDma Simple S2MM 写 8192 字节
  -> CPU Invalidate g_adc_raw_buffer
  -> ADC 统计和 4096 点 FFT
```

硬件每 4096 个 AXIS 握手产生 `TLAST`。DMA 是 simple-mode、S2MM-only、
轮询，没有 DMA 中断。

当前恢复逻辑需要特别区分：

- DMA 启动失败、超时或状态错误后，`dma_recover_s2mm()` 会复位 DMA，并用独立丢弃缓冲消费到一个 `TLAST`；
- 正常初始化后 `g_dma_needs_realign=0`，KEY1 后第一帧不会先执行丢弃对齐；
- 主流程没有核对 BTT 是否正好为 `0x2000`；
- 主流程没有在采集前后各读一次 monitor，因此不能把 blocked/reset/frame 增量原子归属到该帧。

所以当前仍是“稳定周期信号的间歇快照”，不是连续无丢帧采集服务。

## 4. 配置层次

```text
User/config/
|- hardware_config.h    固定 PS/PL 契约：XPAR、帧长、采样率、寄存器偏移
|- algorithm_config.h   FFT、候选、容差、超时和轮询默认值
`- signal_profiles.c/h  题目模式、频带、栅格和确认帧数
```

当前只有 `PROFILE_OLD_SEPARATOR` 配置了有效参数并被主流程使用。AM、ASK、
2FSK、FM、通用测量和微弱信号 profile 只是零值占位，不代表对应功能已实现。

## 5. 硬件边界

| 模块 | PS 访问方式 | 当前封装 |
| --- | --- | --- |
| ADC 数据 | AXI DMA S2MM 到 `g_adc_raw_buffer` | `dma_utils` |
| FIFO/AXIS 状态 | AXI-Lite monitor 寄存器 | `fifo_monitor` |
| 单频 I/Q | AXI-Lite shadow/commit/result | `iq_demodulator` |
| 双 DDS | AXI BRAM 十字快照，最后写 `COMMIT_SEQ` | `dds_control` |
| 按键 | PS GPIO/MIO/EMIO，低有效 | `button_input` |

模式代码目前仍可直接看到 Xilinx 类型（如 `XAxiDma` 和 CMSIS FFT 实例），
因为统一 API 尚未屏蔽这些底层细节。

## 6. 一次锁定与输出

```text
KEY1
  -> dma_capture_frame()
  -> Cache Invalidate
  -> signal_analyze_frame(..., profile, &measurement)
  -> 残差/栅格检查
  -> 连续 profile->confirm_frames 帧一致
  -> dds_control_from_component(A/B)
  -> dds_control_commit(..., phase_reload=1, run=1)
  -> iq_demodulator_measure(A)
  -> iq_demodulator_measure(B)
```

锁定后 IQ 只是一次补充测量，不参与未知频率搜索，也不持续更新 DDS。

## 7. 日志与错误定位

现有日志前缀已经按故障域区分：`[APP]`、`[ADC]`、`[DMA]`、`[FIFO]`、
`[FFT]`、`[IQ]`、`[DDS]`。但还没有统一 `signal_error_t`，调用者通常只能
得到成功/失败，具体第一失败点仍要读串口日志。
