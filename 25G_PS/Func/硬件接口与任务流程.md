# PS 硬件接口、初始化与任务流程

## 1. 真实调用链

```text
main()
  |- xTaskCreate(signal_separator_task)
  `- vTaskStartScheduler()

signal_separator_task()
  `- signal_separator_run()
      |- signal_api_init(&api, profile)
      |- ARMED：统一按键 API 等待 KEY1，DDS 保持停止
      |- ALIGN：signal_align_capture() reset DMA 并丢弃至 TLAST
      |- LOCKING：signal_capture() + signal_identify_components()
      `- RUNNING：signal_dds_apply()，A/B 各做一次 signal_iq_measure()
```

`signal_separator_app.c` 只保留比赛业务顺序、连续确认和日志决策；DMA、Cache、
FFT 工作区、IQ、DDS BRAM、GPIO 和 monitor 的组合集中在 `signal_api.c`。

## 2. 初始化顺序

典型入口：

```c
signal_api_t api;
const signal_profile_t *profile = signal_profile_default();
signal_error_t error = signal_api_init(&api, profile);
```

`signal_api_init()` 的真实顺序：

1. 用 `signal_profile_is_configured()` 校验 profile，并保存 `profile/mode`；
2. `iq_demodulator_init()` 绑定 IQ AXI-Lite 基址；失败只标记不可用；
3. `dma_init_s2mm()` 查 BSP 设备、验证 simple S2MM-only、复位 DMA并关中断；
4. `arm_rfft_fast_init_f32()` 初始化固定 4096 点 RFFT；
5. `button_input_init()` 初始化 MIO/EMIO GPIO；
6. `fifo_monitor_init()`、首次快照和 sticky clear；失败只标记不可用；
7. `dds_control_init()` 绑定控制 BRAM并建立提交序号；
8. 原子提交 `run=0` 的 A/B 停止配置，使 DAC 输出中点；
9. 设置 `api.initialized=1` 并返回 `SIGNAL_OK`。

启动算法自测 `signal_run_self_tests()` 仍由比赛模式决定是否运行，它不属于硬件
初始化，也不访问 DMA/PL。

## 3. BSP 映射与禁止事项

自研代码通过 `hardware_config.h` 引用 BSP 宏，没有在驱动中写死 PL 基地址：

| 能力 | BSP 来源 |
| --- | --- |
| ADC DMA | `XPAR_AXI_DMA_ADC_DEVICE_ID` |
| FIFO monitor | `XPAR_AD_FIFO_MONITOR_AXI_0_AD_FIFO_MONITOR_AXI_BASEADDR` |
| DDS BRAM | `XPAR_AXI_BRAM_CTRL_0_S_AXI_BASEADDR` |
| PL IQ | `XPAR_IQ_DEMODULATOR_0_BASEADDR` |
| PS GPIO | `XPAR_XGPIOPS_0_DEVICE_ID` |

寄存器偏移是自有 IP/BRAM 协议的一部分，集中放在 `hardware_config.h`；模式层
不得出现 `Xil_In32/Xil_Out32`。不要修改自动生成的 BSP、`xparameters.h`、
`Debug/*.mk` 或 PL RTL 来完成 PS 架构整理。

## 4. DMA、Cache 和帧边界

### 4.1 固定硬件契约

- 单路 AXI DMA，SG mode，S2MM-only；
- AXIS 16 bit，内存侧 64 bit，无 DRE；
- 每 4096 个有效 AXIS beat 产生一次 `TLAST`；
- 正式帧为 4096 个 `u16`，即 8192 字节；
- `M_AXI_SG` 和 `M_AXI_S2MM` 均经 HP0 访问 DDR；
- S2MM IOC/error 通过 BSP 中断 61 唤醒 FreeRTOS 所有者任务；
- 当前每次只有一个接收 BD 在途，保持同步单帧 API；
- 原始数据在 `g_adc_raw_buffer`，位于 `.dma_buffer` 并按 64 字节对齐。

### 4.2 为什么 KEY1 后先 ALIGN

`ARMED` 状态没有提交 DMA，但 ADC 和 FIFO 仍运行。等待按键期间 FIFO 会填满，
其中保存的读起点不保证正好是新帧第一个 sample。直接启动正式 DMA 可能先遇到
当前旧帧的 `TLAST`，形成短帧。

当前流程改为：

```text
KEY1 accepted
  -> signal_align_capture()
       -> monitor_before
       -> reset/reinitialize S2MM
       -> 独立 discard buffer 接收到下一个 TLAST
       -> monitor_after
  -> signal_capture() 采正式 8192-byte 帧
```

`signal_align_capture()` 每次新的 ARMED 测量只调用一次。DMA 启动失败/超时后的
`signal_recover()` 也使用同一恢复语义。

### 4.3 一次正式采集的所有权

```text
CPU 取 monitor_before
  -> DCache Flush g_adc_raw_buffer
  -> DMA owns buffer，S2MM 写入
  -> DMA idle/error/timeout
  -> DCache Invalidate g_adc_raw_buffer
  -> CPU owns buffer
  -> 取 monitor_after + 读取实际 BTT
  -> 构造 signal_frame_t
```

调用者只在 `signal_capture()==SIGNAL_OK` 且 `frame.frame_valid!=0` 后读取
`frame.samples`。下一次采集会覆盖同一静态缓冲；若要长期保存，调用者必须在
下一次采集前复制所需数据。

## 5. 帧质量和 monitor 语义

API 保存采集前后的 `fifo_monitor_snapshot_t`，并形成以下标志：

| 标志 | 判定 |
| --- | --- |
| `SIGNAL_FRAME_QUALITY_SHORT` | DMA 报告字节数不是 8192 |
| `SIGNAL_FRAME_QUALITY_FIFO_BLOCKED` | 采集期间 blocked-full 累计值增长 |
| `SIGNAL_FRAME_QUALITY_RESET_BLOCKED` | 采集期间 reset-busy blocked 累计值增长 |

短帧直接返回 `SIGNAL_ERR_FRAME_INVALID` 并增加 `bad_frame_count`。blocked 标志
当前只记录，不自动拒帧：现有架构在间歇 DMA、FIFO 已满的条件下可能在开始
排空时出现 blocked 增量，若无板级数据就强制拒绝会改变已验证功能。后续若要
增加严格帧质量策略，应先记录板上正常帧的 monitor 增量，再在 API 内统一增加，
不能由各模式自行判断。

`signal_status_t` 的关键计数：

- `capture_count`：DMA 完成并形成帧描述符的次数；
- `dma_error_count`：对齐或正式采集的 DMA 失败次数；
- `bad_frame_count`：DMA 完成但实际长度不是 8192 的次数；
- `alignment_count`：成功执行启动/恢复对齐的次数；
- `last_dma_length_bytes`：最近一次正式 S2MM 报告的长度。

## 6. 配置分层

```text
User/config/
|- hardware_config.h    不随题目变化：XPAR、帧长、时钟、寄存器协议
|- algorithm_config.h   现有算法实现常量：FFT 长度、候选数、谐波数、轮询超时
`- signal_profiles.c/h  随题目变化：频带、栅格、锁定、波形、DDS 和相位参数
```

当前只有 `PROFILE_OLD_SEPARATOR` 参数完整。其余 profile 是明确的未来占位项，
不会通过 `signal_profile_is_configured()`，也不能初始化 API。

## 7. 一次锁定和输出

```text
KEY1
  -> ALIGN 一次
  -> signal_capture(&api, &frame)
  -> signal_identify_components(&api, &frame, &measurement)
  -> profile 残差/栅格检查
  -> 连续 profile->confirm_frames 帧一致
  -> signal_dds_build_pair(&api, &locked, phase, &pair)
  -> signal_dds_apply(&api, &pair)
  -> signal_iq_measure(A)
  -> signal_iq_measure(B)
```

锁定后 IQ 仍是一次补充测量，不参与未知频率搜索，也不持续更新 DDS。运行中
T17/R17 通过 `signal_dds_adjust_b_phase()` 调整 B 相位；N16 通过
`signal_dds_stop()` 停止并返回 `ARMED`。

## 8. PS/PL 功能边界

| 模块 | 归属 | 当前职责 |
| --- | --- | --- |
| AD9226 采样、CDC、FIFO、AXIS/TLAST | PL | 产生固定帧流 |
| DMA/Cache/帧描述符 | PS `signal_api` | 间歇快照采集和恢复 |
| 双分量 FFT/拟合 | PS 算法 | 未知频率搜索和正弦/三角分类 |
| 单频 I/Q 积分 | PL，PS 配置/解释 | 已知频点幅相特征 |
| DDS 相位累加、ROM、DAC | PL | 连续波形输出 |
| DDS 参数/profile/原子提交 | PS | 构造并提交 A/B 配置 |

本次没有改 PL 数据通路、DMA 模式、IQ IP、DDS 协议或 FreeRTOS 任务拓扑。

## 9. 编译入口

优化级别由 `Identification_Processing_System/.cproject` 管理，Debug C/C++ 为
`-O2`。不要手改 `Debug/src/**/subdir.mk`。新增 `.c` 后应让 Vitis 重新扫描
应用源目录，再使用：

```text
25G_PS/script/ps_rebuild_system.bat
```

构建脚本会检查生成规则包含 `-O2`，然后清理并构建应用 ELF。
