# 2026 G 硬件接口与任务流程

## 活动数据路径

```text
模拟低通/可选增益 -> ADC 5.120060 MHz
                    -> 冻结的 PL FIR /3
                    -> AXI4-Stream, 4096 x signed16, TLAST=8192 byte
                    -> Zynq PS SG DMA
                    -> CMSIS RFFT + 谐波联合拟合
                    -> 串口结果/内存模型波形
```

PL 本次继续冻结。PS 必须按 `s16` 解释 DMA 数据，分析采样率固定为 `5120060 / 3 Hz`，不得再执行旧链路中的 `u16 >> 4` 或额外 PS FIR。

## KEY1/KEY2 状态机

```text
启动初始化 -> ARMED
ARMED + KEY1
  -> DMA 对齐
  -> 丢弃 3 个完整预热帧
  -> 采集第 4 个正式帧
  -> 校验帧长与 blocked_reset，记录反压告警
  -> 分析并打印结果
  -> HOLD
HOLD + KEY2
  -> 清除结果和监视器粘滞状态
  -> ARMED
```

- KEY1 只在 `ARMED` 状态触发新测量，避免重复按键覆盖正在保持的结果。
- KEY2 清除结果并重新装填；清除后再次按 KEY1 可以重复完整测量。
- 正式帧实收必须严格等于 8192 byte，否则本次测量硬拒绝。
- 正式帧采集期间 `blocked_reset` 计数若有增长，本次测量硬拒绝。
- `blocked_high_watermark` 在单 BD 间歇采集中可能只是预期反压，只告警并记录，不作为硬拒绝条件。

当前流程有意采用一个 BD 循环复用、逐帧等待完成的现有 SG DMA 接口。题目当前要求是按键触发和结果保持，不需要为连续实时刷新改写多 BD 环形队列；若后续确实加入实时 HMI，再增加连续环形采集。

## DMA 与缓存顺序

1. DMA 写入前刷新目标缓冲区对应缓存范围。
2. 调用现有 `dma_align_s2mm` 完成流边界对齐。
3. 用 `dma_capture_frame` 复用同一 BD，顺序接收 3 个预热帧和 1 个正式帧。
4. 正式帧完成后使缓存失效，再由 CPU 读取。
5. 用 `dma_last_s2mm_length_bytes` 确认 TLAST 对应的实收长度严格等于 8192 byte。

FIFO monitor 位于现有硬件监视点，只能作为链路异常的辅助判断；它若位于 FIR 前，不能单独证明 FIR 输出与 DMA 帧内容完全正确。因此当前只将正式帧期间新增的 `blocked_reset` 作为硬错误，`blocked_high_watermark` 仅作反压告警。

## 模拟前端策略

模拟低通是当前确定保留的前级。放大器可以先旁路完成数据通路和算法 bring-up，但最终是否旁路必须由弱信号误差与满量程余量共同决定。

按 10 Vpp、12 位 ADC 计算，直连约为 `2.44140625 mV/code`，题目允许的 `5 mVpeak` 分量只有约 2 code，通常不足以支撑最终精度。因此最终硬件大概率仍需在低通后配置合适增益，同时验证最大输入不削顶。`0.1645 mV/code` 只代表当前放大链的初始换算参数；直连板测必须切换为约 `2.44140625 mV/code`，两种接法最终都必须做端到端标定。

## 当前不包含

- IQ/DDC、signal separator 或 PL DDS。
- 连续 DMA 刷新和多 BD 环形队列。
- HMI 协议、波形传输或界面实现；当前仅保留波形生成 API 供后续使用。
